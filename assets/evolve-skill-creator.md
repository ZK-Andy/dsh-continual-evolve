# Evolve Skill Creator（自创）

> 自创技能，仿官方 `skill-creator` 的结构（出处：`anthropics/skills` 的 skill-creator 模板）按本项目门禁改写。只产出**内容**（标题＋钩子＋正文），不写任何落盘指令——存储由插件代码负责。

## 命名（先定名字，再写内容）

1. 一律 `evolve_` 前缀 + 短横线小写（kebab），如 `evolve-deploy-checklist`。`dsh-*` 是上游原样保留的名字，自创技能不准占用。
2. 名字即路由的一部分：看到名字就能猜出它干什么，猜不出就改名，不靠正文解释。

## 访谈（动笔前问清三件事）

1. 这条技能让模型**做什么**？（一句话能说清吗？说不清就继续拆。）
2. **何时触发**？（用户原话是什么？什么上下文里该想起它？要 2–3 个具体说法，不要"需要时使用"。）
3. 输出是什么样子？（步骤清单 / 检查表 / 固定格式？有没有反例——什么情况下**不该**用它？）

## 正文结构

用祈使句写，短句，< 150 行。超出就拆成主技能 + 被引用的附文，并在正文里写清何时去读附文。

- **标题**：一句话，说清本事，不超过 200 字。
- **触发钩子**（description）：做什么 ＋ 何时用。做法是：标题一句话 ＋ 首个有意义正文行的改写（`标题 — use when: …`），不超过 240 字、必须单行。目录匹配只看这一行，标题党式的钩子等于不存在。
- **正文**（body）：步骤或规则本身。第一行要是干货——第一行决定了钩子质量，也决定了读者第一眼。

## 本项目门禁（写完逐条自检，不过就改）

- [ ] 标题、钩子、正文三件齐全且非空；正文不超过 65536 字。
- [ ] 全文不带任何密钥痕迹（API key、token、私钥块、账号密码赋值一律不出现；占位符用全大写 `YOUR_KEY_HERE` 形）。
- [ ] 不同 id 不写相同正文（先检索，没有才新建；已有就更新那条）。
- [ ] 正文里没有持久化指令：不出现"调用 skill_write""写入 SKILL.md""保存到全局"这类句子。成稿后把正文交给用户，由调用方落盘。

## 不做

- 不给技能加类型、评分、置信度；没有晋升机制，搬到全局只走用户明确的手动搬家。
- 不写"自动同步/自动更新"——技能是版本化文本，改一次就是一次提交。
