<h3 id="cn-v0.14.2">v0.14.2 — 工作区选择器可用性与外观修复</h3>

### 问题修复

- **下拉"点了没反应"**（@ZK-Andy）：v0.14.1 的自绘列表把外点监听挂在 `document` 的 `click` 上，而 React 18 对离散事件会**同步 flush 副作用**——"打开菜单的那次 click"冒泡到 `document` 时立刻命中刚挂上的监听器，列表刚开就被关掉，观感是按钮坏了、切换不了。列表改用**宿主原生 `Menu` 原语**（外点与 Escape 由它处理，dshmarket 生产在用）；老宿主回退路径改为 `pointerdown` + 容器包含判断。根因与正解记入 `docs/FAQ.md` #8。
- **外观对齐 ZCode**（@ZK-Andy）：触发按钮改用宿主 `Button`（`outline` + `md` 尺寸 + 文件夹图标 + 圆角胶囊；此前是 `sm` 且无图标）；列表换成宿主菜单面（选中态带勾）；选项只显示工作区名（去掉根路径第二行）；文件行加上宿主 `FileTypeIcon` 类型图标，与 ZCode 查看器一致。

### 其他改动

- 测试 91 → 92：bundle 形态断言新增"不得再出现 click 外点监听"的回归守卫，并新增一条走宿主 `Menu` 路径的端到端用例。

### 升级提示

- dotnet-desktop 是 npm 实体拷贝：更新到 0.14.2 并重启 profile 后**请硬刷新 GUI 页面**（Ctrl+Shift+R），避免浏览器继续用旧的 client bundle。
- 验收：①点工作区下拉能展开并切换（本机应列出 `work` 与 `dotnet-deepseek-harness-desktop`）②「刷新」按钮真的重载 ③注入回归。
- `memoryIndex.*` 与 `memoryCard.enabled` 配置与行为无任何变化。

<h3 id="en-v0.14.2">v0.14.2 — workspace selector usability and looks</h3>

### Bug Fixes

- **Dropdown did nothing** (@ZK-Andy): the v0.14.1 hand-rolled list attached its outside-click listener to `document`'s `click`, and React 18 flushes effects synchronously for discrete events — the very click that opened the list bubbled to `document` and hit the freshly attached listener, closing it again, so the button read as dead and switching was impossible. The list now uses the host's own `Menu` primitive (it owns outside-click and Escape; dshmarket ships it); the old-host fallback listens on `pointerdown` with a wrapper containment check. Root cause and fix: `docs/FAQ.md` #8.
- **Looks aligned with ZCode** (@ZK-Andy): the trigger is the host `Button` (`outline`, `md`, folder icon, pill radius — it was `sm` with no icon); the list is the host menu surface with a check-marked selection; rows show the workspace label only (the root-path line is gone); file rows carry the host `FileTypeIcon` category tile like ZCode's viewer.

### Chores

- Tests 91 → 92: the bundle-shape case now guards against an outside-click listener returning, plus a new end-to-end case over the host `Menu` path.

### Upgrade notes

- dotnet-desktop installs an npm copy: update to 0.14.2, restart the profile, and **hard-refresh the GUI page** (Ctrl+Shift+R) so the browser does not keep serving the previous client bundle.
- Check: ① the workspace dropdown opens and switches (this machine should list `work` and `dotnet-deepseek-harness-desktop`) ② the refresh button really reloads ③ injection regression.
- `memoryIndex.*` and `memoryCard.enabled` configuration and behavior are unchanged.
