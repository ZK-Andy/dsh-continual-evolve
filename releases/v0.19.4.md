<h3 id="cn-v0.19.4">安全修复与升级注意</h3>

- **凭据门禁覆盖带前缀的名字（`60ed881`，@ZK-Andy）**：credential-assignment 模式名前的 `\b` 在 `_` 前不成立，导致带前缀的赋值全部漏判。改为零宽后顾 `(?<![A-Za-z0-9])`：`-`、空白、标点与串首行为不变，唯一多放行的就是 `_` 前缀位；单次命中的匹配文本与脱敏输出逐字不变。新增五类前缀名回归（`MY_API_KEY`、`OPENAI_API_KEY`、`GITHUB_TOKEN`、`DB_PASSWORD`、`APP_SECRET`），回退旧边界必红。理由见 ADR `2026-11-03-secret-prefixed-credential-bypass`。
- **升级前请读：存量条目会被巡检重判**。守卫不只拦新增：`quarantineSecrets` 会对全部 active 记忆、技能与 prompt 重新判定，而 applied 抽取后会自动触发巡检。升级后首次巡检会把库中已有的 `MY_API_KEY="…"` 类行隔离；若被隔离的是技能条目，其托管文件会被删除（手写文件保留并记 warning）。这是本次修复的预期行为——命中即隔离，不做例外。
- **已知缺口（本笔未扩面）**：无引号赋值（`MY_API_KEY=abc…`）、camelCase 前缀（`myApiKey`）、`_` 后缀名（`SECRET_KEY`、`PASSWORD_HASH`、`API_KEY_ID`）、值含 `${}` 插值的形态仍不在守卫内；与「凭据类字段名 = 引号长字面量即拦」的承诺不完全对齐，后续按实例评估。

<h3 id="en-v0.19.4">Security Fix and Upgrade Note</h3>

This is a **security fix release**: it closes the credential-gate bypass reported in dsh-bounty #904 — standard env spellings such as `MY_API_KEY="…"`, `OPENAI_API_KEY="…"`, and `GITHUB_TOKEN="…"` could slip past `secretLeakReason` into the memory store. It also records the project's status in the README (feature-frozen, low-frequency maintenance). 950 tests / 77 files, all 22 gates proven red/green, CI green.

- **The leak guard now covers prefixed credential names (`60ed881`, @ZK-Andy)**: the `\b` before the name in the credential-assignment pattern never matches before `_`, so prefixed assignments were all missed. It is replaced by the zero-width lookbehind `(?<![A-Za-z0-9])`: behavior after `-`, whitespace, punctuation and at string start is unchanged, and the only newly admitted position is the `_` prefix. For a single hit, the matched text and redaction output stay byte-identical. Five regression cases cover the prefixed names (`MY_API_KEY`, `OPENAI_API_KEY`, `GITHUB_TOKEN`, `DB_PASSWORD`, `APP_SECRET`) and fail if the old boundary returns. Rationale: ADR `2026-11-03-secret-prefixed-credential-bypass`.
- **Read before upgrading: existing rows are re-judged by patrol**. The guard does not only stop new writes: `quarantineSecrets` re-judges every active memory, skill and prompt, and patrol runs automatically after an applied extraction. On the first patrol after upgrade, rows already in the store that contain `MY_API_KEY="…"`-style lines are quarantined; if the quarantined entry is a skill, its managed files are removed (hand-written files are kept with a warning). This is intended — a hit is quarantined, no exceptions.
- **Known gaps (out of scope here)**: unquoted assignments (`MY_API_KEY=abc…`), camelCase prefixes (`myApiKey`), `_`-suffixed names (`SECRET_KEY`, `PASSWORD_HASH`, `API_KEY_ID`), and values containing `${}` interpolation are still not covered. The promise "credential-like field name = quoted long literal is blocked" is therefore not fully aligned for these shapes; they will be evaluated per instance.
