<h3 id="cn-v0.15.13">v0.15.13 — 通用子代理与装载器：插件里「有几个子代理」第一次读得出来</h3>

老问题是从一次评审失败里冒出来的：技能条目被反复拒，理由却是「记忆库的内容评审门」的口径——因为插件里四个评审岗位只有三份说明书，技能便宜门根本不存在，被记忆门的提示词顶替。往下挖是同一个结构病：所有 LLM 调用都内联在调用点，身份、提示词、预算、解析散在各处，"有哪些子代理、各自被交待了什么"从代码里读不出来；限制内联还让「同一个模型间歇砍断自己的判定」这种设计级毛病无从一处修正。本版把调用收进一个装载器、把定义收进一张表，并顺手补上两轨账本一直答不出的两个问题：失败调用跑在哪个模型、烧了多少 token。

### 新功能

- **子代理定义表 + 装载器是唯一调用路径**（@ZK-Andy，`a0b5ca4`）：六份定义（评审四岗位 + 提取两岗位）声明在 `src/subagent-defs.ts`，每份带身份、完整 system 提示词、预算兜底与应答解析器；feature 代码只经 `subagentLoaderFor(...).run(定义, prompt)` 调用，不再 import 传输层——`test/subagent.test.ts` 有一条结构性回归锁死这点。**技能便宜门补位**：记忆与技能的家规相反（记忆要求抹掉仓库名仍成立，项目技能本来就该绑仓库），四个岗位现在各装各的说明书，不再靠 prompt 散文分支。
- **执行骨架是模板方法、流程推进是责任链**（@ZK-Andy，`a0b5ca4`/`5d8eb4b`）：装配 → 调用 → 解析 → 记账固定，差异全由定义注入；评审环＝门 → 昂贵门 → 落盘（`src/review-ring.ts`）、提取环＝预检门 → 提案调用（`src/extraction-ring.ts`），链路由环境类组装，缺终局环节即 fail loud。批量循环/队列/调度留在 `review.ts`、`review-candidates.ts`、`extraction.ts`，两个此前超预算的大文件随之回到 400 行内。
- **失败即值：失败行也带路由与用量**（@ZK-Andy，`ace0b15`）：调用失败现在抛 `SubagentCallError`，随错误带上已观测的 `usage` / `finish` / `route`（截断答案走同一条路）。真库体检里 8 条 `gate-llm-failed` 的 usage 全空、`llm-failed` 行的 `model` 全为 null——「某次门失败跑在哪个模型、烧了多少」账本答不出的问题，从这一版起答得出。
- **`review_log` 增加 `model` 列**（@ZK-Andy，`29f30c3`）：每条 verdict 行（含失败行）都记路由模型，与 `extraction_log` 对齐；旧库经 `ALTER TABLE` 自动迁移，已用真库副本实测。
- **输出预算改按模型能力推导**（@ZK-Andy，`ace0b15`）：取模型自己广告的 per-request 输出上限（`defaultMaxTokens`），定义里的数值只做兜底，与推理档位共用同一次能力查询——「同一模型同一预算间歇撞 max-tokens」从设计层消失，而不再靠把 512 改成 1024 这类猜测。

### 问题修复

- **feedback 提示语不再被回抄进改写正文**（@ZK-Andy，`afb6b89`）：Why/How 契约只留在 system 提示词与落盘门禁里，不再紧跟条目正文（模型会把紧邻正文的提醒当内容抄回去）。补两条回归：evolve prompt 不含该提示语、feedback 缺 Why 的提案落盘被拒。

### 升级提示

- 无破坏性变更。旧库首次打开自动补 `review_log.model` 列（真库副本实测：列已加、带 model 的行可读回）。
- dotnet-desktop 是 npm 实体拷贝：更新到 0.15.13 后**重启 App** 即生效（`client/` 本版未动，无需硬刷）。
- 评审环保持试运行（`review.dryRun` 默认开）：本版不改开关，只补账本可读性——返厂后请重点看每行的 `model` 列与门/贵调用失败行是否带上 usage。
- 测试 363 → 395 例（新增 32 例：定义表/装载器骨架/责任链/预算推导/失败携带观测，以及评审与提取两轨的账本断言）；typecheck / lint / 文档门禁 / `check:pack` 全绿。

<h3 id="en-v0.15.13">v0.15.13 — one loader for every subagent: the plugin's LLM jobs are readable at last</h3>

The old problem surfaced as a review failure: skill entries kept getting rejected under the memory gate's rubric — because of the plugin's four review jobs, only three prompts existed. The skill cheap gate did not exist at all; the memory gate's prompt stood in for it. Underneath sat one structural disease: every LLM call was inlined at its call site, so identity, prompt, budget and parsing were scattered, "which subagents exist and what each one is told" could not be read from the code, and inlined limits made a design-level defect — one model intermittently cutting its own verdict off — impossible to fix in one place. This release moves the calls behind one loader and the definitions into one table, and closes two questions both ledgers could not answer: which model a failed call ran on, and how much it burned.

### Features

- **A subagent definition table, with the loader as the only call path** (@ZK-Andy, `a0b5ca4`): six definitions (four review jobs, two extraction jobs) are declared in `src/subagent-defs.ts`, each carrying its identity, full system prompt, budget fallback and answer parser; feature code calls only through `subagentLoaderFor(...).run(definition, prompt)` and never imports the transport — a structural regression in `test/subagent.test.ts` locks that in. **The skill cheap gate now exists**: memory and skill home rules are opposites (a memory must survive having its repo name stripped; a project skill is supposed to be repo-bound), and the four jobs each load their own prompt instead of relying on prose branches inside a shared one.
- **Template-method skeleton, responsibility-chain flow** (@ZK-Andy, `a0b5ca4`/`5d8eb4b`): assemble → call → parse → account is fixed, with differences injected by the definition; the review ring is gate → evolve → landing (`src/review-ring.ts`) and the extraction ring is pre-gate → proposal call (`src/extraction-ring.ts`). The chain is assembled by the environment class, and a chain with no terminal link fails loud. Batch, queue and schedulers live in `review.ts`, `review-candidates.ts` and `extraction.ts`; the two files that had outgrown the size budget are back under 400 lines.
- **Failures are values: failed calls carry their route and usage** (@ZK-Andy, `ace0b15`): a failed call now throws `SubagentCallError` carrying the observed `usage` / `finish` / `route` (cut answers travel the same path). In a production audit, all 8 `gate-llm-failed` rows had empty usage and every `llm-failed` row had a null `model` — "which model did this gate failure run on, and how much did it burn" was unanswerable from the ledger, and is answerable from this release on.
- **`review_log` gains a `model` column** (@ZK-Andy, `29f30c3`): every verdict row — failures included — records the route model, aligned with `extraction_log`; older databases migrate through `ALTER TABLE`, verified against a copy of the real database.
- **Output budget derived from model capability** (@ZK-Andy, `ace0b15`): the exact model's own advertised per-request cap (`defaultMaxTokens`) wins, the definition's number is only the fallback, and effort and budget share one capability query — "the same model intermittently hitting max-tokens at the same budget" disappears at the design level instead of being guessed away by moving 512 to 1024.

### Bug Fixes

- **The feedback reminder can no longer be copied back into a rewrite** (@ZK-Andy, `afb6b89`): the Why/How contract stays in the system prompt and the landing gates, never adjacent to the item body (the model treated a reminder next to the text as content). Two regressions pin it: the evolve prompt does not contain the reminder, and a feedback proposal without a Why line is refused at landing.

### Upgrade notes

- No breaking changes. Older databases gain the `review_log.model` column on first open (verified on a copy of the real database: column added, rows with a model readable back).
- dotnet-desktop is an npm copy: update to 0.15.13 and **restart the app** (`client/` is untouched, no hard refresh needed).
- The review ring stays in trial mode (`review.dryRun` defaults on): this release changes no switch, only ledger readability — after the update, watch each row's `model` column and whether gate/evolve failure rows carry usage.
- Tests 363 → 395 (32 new: definition table, loader skeleton, responsibility chain, budget derivation, failure observations, plus ledger assertions on both the review and extraction tracks); typecheck, lint, docs gates and `check:pack` all green.
