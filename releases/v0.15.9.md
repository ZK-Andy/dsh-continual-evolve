<h3 id="cn-v0.15.9">v0.15.9 — 门挂了要留原文：别让「门死了」和「没门」长得一样</h3>

上一版给提取补了便宜预检门，但门自己抛错时 catch 是空的。fail-open 本身是对的（透传给贵调用，永不 stall），可失败不留痕：贵调用行的 `cheap_usage` 为空，既可能是「门挂了」，也可能是「这版还没有门」。上线当晚就踩到了——桌面端 18:44 更新重启后，带思考强度的模型上 22 次全调用门全灭（唯一一次命中门的是另一个模型），而宿主日志不落请求级错误，账本上一点痕迹都没有。本版把这条缝上。

### 问题修复

- **提取门失败留痕**（@ZK-Andy，`4702525`）：`extraction_log` 新增 `cheap_error` 列（独立的单列 ALTER 迁移，已经带 `cheap_usage` 的库照样补上）。门调用抛错时，错误原文（压平空白、截 200 字符）落到**该次运行自己的终局行**上——skipped / failed / applied 三条路径都带。fail-open 语义不变：不消费游标、不 stall、一次运行仍是一行，终局原因不被改写。provider 抛错原文自带 `max_tokens` / `outputTokens` / `reasoningTokens`，直接回答「门是在烧满预算之后死的，还是路由抖动」。
- 测试 328 → 330 例（门抛错 + 贵调用落盘 / 跳过两条回归、迁移断言两列齐备），typecheck/lint/文档门禁/`check:pack` 全绿；覆盖率门禁全文件达标。

### 其他改动

- **门继续走会话路由的模型**（@ZK-Andy，`bdd4251`）：不单独给门指定轻量模型——用户按任务切模型，门与正文不同模型会让「值不值得提」的判断随模型漂移，还多一层配置面。门预算（当前 512）是否调大，仍待真库原文落地后单独决定。

### 升级提示

- 无配置变更、无破坏性变更；新列 `cheap_error` 旧库打开即迁，无需手动迁移。
- dotnet-desktop 是 npm 实体拷贝：更新到 0.15.9 后**重启 App** 即生效（`client/` 本版未动，无需硬刷）。
- 验收：`SELECT ts, skip_reason, cheap_error FROM extraction_log WHERE cheap_error IS NOT NULL ORDER BY ts DESC LIMIT 5`——若你的日常模型上门还在挂，这里会直接给出原文。

<h3 id="en-v0.15.9">v0.15.9 — a dying gate leaves its error text: "gate is dead" must not look like "no gate at all"</h3>

The previous release added the extraction cheap pre-gate, but its `catch` was empty. Fail-open was the right call (pass through to the full call, never stall) — yet a failure left no trace: an empty `cheap_usage` on a full-call row could mean "the gate died" or "this build has no gate". That bit the very evening it shipped: after the desktop app restarted at 18:44, every one of 22 full calls on a reasoning model had a silent gate (the one call that got through the gate used another model), and the host logs no request-level errors — the ledger showed nothing. This release closes that gap.

### Bug Fixes

- **Failed-gate ledgering** (@ZK-Andy, `4702525`): `extraction_log` gains a `cheap_error` column (its own single-column ALTER, so stores that already carry `cheap_usage` still migrate). When the gate call throws, the flattened, capped (200 chars) error head lands on **the run's own terminal row** — skipped / failed / applied alike. Fail-open semantics are untouched: no cursor consumption, no stall, one run stays one row, and the terminal reason is never rewritten. The provider's own numbers (`max_tokens` / `outputTokens` / `reasoningTokens`) ride the same text, answering "did the gate die after burning its whole budget, or was the route flapping?".
- Tests 328 → 330 (gate throws + full call lands / gate throws + model skip, plus the migration asserting both columns); typecheck, lint, docs gates, and `check:pack` all green; per-file coverage floors held.

### Chores

- **The gate keeps using the session's routed model** (@ZK-Andy, `bdd4251`): no separately pinned lightweight gate model — the user switches models per task, so a different gate model would make the "worth extracting?" verdict drift with the model and add another config surface. Whether the gate's 512-token budget should grow stays a separate decision, pending real-ledger error text.

### Upgrade notes

- No config or breaking changes; the new `cheap_error` column migrates on first open, no manual step.
- dotnet-desktop is an npm copy: update to 0.15.9 and **restart the app** (`client/` is untouched this release, no hard refresh needed).
- Acceptance: `SELECT ts, skip_reason, cheap_error FROM extraction_log WHERE cheap_error IS NOT NULL ORDER BY ts DESC LIMIT 5` — if your daily model still kills the gate, the error text is right there.
