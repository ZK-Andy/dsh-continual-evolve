<h3 id="cn-v0.15.2">v0.15.2 — 卡片默认打开宿主当前工作区</h3>

修一个 v0.15 换存储时被悄悄改掉的语义（@ZK-Andy 桌面端实测）：**卡片总是打开在另一个工作区**——人在 `work`，卡片却选中 `dotnet-deepseek-harness-desktop`。

### 问题修复

- **卡片默认工作区改为"宿主当前工作区"**（@ZK-Andy，`a4892b7`）：卡片的初始选中一直是"列表首条"这个隐式规则——选中态初值为空，为空就取 `workspaces[0]`。v0.14.x 的列表源是宿主工作区注册表（stable registry order），v0.15 换成库查询后，首条的含义变成了 `MAX(updated_at) DESC`，也就是"**最近写过记忆的分区**"：另一工作区的一条 import 比本工作区的新，卡片就打开了它。现在 `/workspaces` 显式回答"该打开哪个"——新增 `defaultRoot`：①宿主注册表里 `updatedAt` 最新、且落在卡片列表内的那条；②取不到时退回库内"最近活动"分区（账本最新 `ts` 与记忆最新 `updated_at` 取更晚者）；③都没有则为 `null`，客户端保持原有的首条回退。提示逐请求解析（卡片开着时新建/切换工作区，刷新即生效），只在已列出的分区里认账，symlink 拼写差异先归一，任何一步失败都降级而不影响列表。

### 升级提示

- 无配置变更、无破坏性变更；列表顺序不变，只有"打开时选中哪个"改变。
- 卡片仍**不持久化**用户的手动选择（本次拍板）：重新打开时回到"当前工作区"。
- dotnet-desktop 是 npm 实体拷贝：更新到 0.15.2 并重启 profile 后，**请硬刷新 GUI 页面**（Ctrl+Shift+R）。
- 验收：在 `work` 工作区打开插件卡片，作用域选择器应默认显示 `work`；切到其他工作区后回来仍按最近活动的那个选中（不记忆手动选择）。

<h3 id="en-v0.15.2">v0.15.2 — the card opens on the host's current workspace</h3>

Fixes a semantic that the v0.15 store swap changed silently (measured on the desktop host, @ZK-Andy): **the card always opened on another workspace** — the session lived in `work` while the card selected `dotnet-deepseek-harness-desktop`.

### Bug Fixes

- **The card's default workspace is now the host's current one** (@ZK-Andy, `a4892b7`): the initial selection had always been the implicit "first row" rule — the selection state starts empty and empty means `workspaces[0]`. The v0.14.x list came from the host workspace registry (stable registry order); once v0.15 sourced the list from the store, "first row" became `MAX(updated_at) DESC`, i.e. **whichever partition wrote a memory most recently** — another workspace's import outranked this one, so the card opened there. `/workspaces` now answers which partition to open on: the new `defaultRoot` is ① the host registry record with the newest `updatedAt` that names a listed partition ② else the store's most recently active partition (the newer of the newest ledger instant and the newest memory write) ③ else `null`, where the client keeps its existing first-row fallback. The hint is resolved per request (a workspace created or switched to while the card is open is picked up on refresh), only ever matches inside the listed set, resolves symlink spelling first, and degrades on any failure without touching the list.

### Upgrade notes

- No config or breaking changes; the list order is unchanged — only which row the card opens on.
- The card still does **not** persist a manual selection (decided in this round): reopening returns to the current workspace.
- dotnet-desktop ships an npm copy: after updating to 0.15.2 and restarting the profile, **hard-refresh the GUI page** (Ctrl+Shift+R).
- Acceptance: open the plugin card while working in `work` — the scope selector should read `work`; after visiting another workspace it follows the most recently active one again (manual picks are not remembered).
