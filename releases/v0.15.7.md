<h3 id="cn-v0.15.7">v0.15.7 — 内容质量自进化环：模型判，代码办</h3>

v0.15.6 验证未达预期后重做的版本：查阅计数只证明被翻过，运行指标只证明跑过——这一版第一次回答"写得好不好"。评审与提取在结构上独立（自有提示词、自有预算、自有账本），全程无人。

### 新功能

- **内容质量自进化环**（@ZK-Andy，`0765882`+`1cfdda4`）：便宜门模型先判某条记忆/技能值不值得细看，批了才跑贵改写——记忆按准确/可用/可复用/不重复/不过时五维打分，技能按触发精度/可执行完备/可复用/不重复四维打分，只输出 keep/rewrite/quarantine 结构化 verdict。新写即审、存量有界积压排空、30 天未动回炉。两条硬保证：删除永不自动落盘（只改写与隔离），超 30% 幅度改写自动转隔离。日上限 100 条（新写 > 被纠正牵连 > 陈旧 > 抽查，尾部丢弃不滚雪球）。每条终态落一行 `item-review` verdict、日合一行 rollup（预算 vs 实审 vs 积压 vs 丢弃，token 按便宜/贵分账）。默认试运行（`review.dryRun` 开）：只记 verdict 不落盘，分布看顺后再关。
- **管线两处加法**（@ZK-Andy，`9935876`）：提案可选 `corrects`（同分区 active 目标、禁自指）+ 账本 `item-review` trigger 预留——正是本版自进化环接上的两个口子。
- **用量心跳补齐**（@ZK-Andy）：`memory_read` 按 id 取正文计一次查阅（`memory_usage`，与技能同纪律）；技能侧两次修正——计数改名"查看 N 次"（`33894c2`）、人工预览永不记数（`c7a912b`）。
- **评审回归整段废除**（@ZK-Andy，`bb35faa`）：要的是沉淀内容评审，造的是运行指标——token-usage/reviewSummary/评审行及测试全撤，ADR 归档 rejected；记账口径（`normalizeUsage`）在本版以 `token-usage.ts` 回归，只做记账不做评审展示。
- 测试 273 → 319 例（新增 46 个评审回归：用量/账本/预算/verdict/护栏/调度），typecheck/lint/文档门禁/`check:pack` 全绿；覆盖率门禁全文件达标。

### 升级提示

- 新增配置 `review.enabled` / `review.dryRun`（默认开）/ `review.dailyBudget`（默认 100）/ `review.batchSize`（默认 10），无破坏性变更；新表全是 `CREATE IF NOT EXISTS`，旧库打开即建，无需迁移。
- dotnet-desktop 是 npm 实体拷贝：更新到 0.15.7 并重启 profile 后，**请硬刷新 GUI 页面**（Ctrl+Shift+R）。
- 验收：试运行期卡片无可见变化；查库可见 `review_log` verdict 行与 `review_daily` 日行——`SELECT * FROM review_daily ORDER BY day DESC LIMIT 7`。

<h3 id="en-v0.15.7">v0.15.7 — content-quality evolution loop: models judge, code acts</h3>

Reworked after v0.15.6 failed acceptance: view counts only prove somebody opened an item, runtime metrics only prove the pipeline ran — this release answers "is it any good" for the first time. Review rides a track independent from extraction (own prompts, own budget, own ledger), with no human in the loop.

### Features

- **Autonomous content-quality loop** (@ZK-Andy, `0765882`+`1cfdda4`): a cheap gate model first decides whether a memory/skill entry deserves a close look; only approvals run the evolve pass — memories scored on accuracy/usability/reusability/duplication/freshness, skills on trigger precision/executability/reusability/duplication, emitting only structured keep/rewrite/quarantine verdicts. New writes reviewed on landing, existing stock drains through a bounded backlog queue, untouched entries requeue after 30 days. Two hard guarantees: delete never lands automatically (rewrite or quarantine only), oversized rewrites degrade to quarantine. Daily cap 100 items (new > corrects-linked > stale > spot-check, tail drops instead of rolling over). Every terminal path lands one `item-review` verdict row plus one daily rollup row (budget vs reviewed vs backlog vs dropped, tokens split by cheap/evolve purpose). Ships in trial mode (`review.dryRun` on): verdicts ledgered, nothing applied — switch off once the distribution reads clean.
- **Two pipeline openings** (@ZK-Andy, `9935876`): optional proposal `corrects` (same-partition active target, no self-reference) plus a reserved `item-review` ledger trigger — exactly the two hooks this loop plugs into.
- **Usage heartbeat completed** (@ZK-Andy): `memory_read` body-by-id counts one view (`memory_usage`, same discipline as skills); skill-side corrections — counter renamed to views (`33894c2`), human card previews never counted (`c7a912b`).
- **Review-loop retrieval fully reverted** (@ZK-Andy, `bb35faa`): it audited runtime metrics while content quality was wanted — token-usage/reviewSummary/card line and tests removed, ADR archived as rejected; the accounting caliber (`normalizeUsage`) returns in this release as `token-usage.ts`, accounting only, no review display.
- Tests 273 → 319 (46 new review regressions: usage/ledger/budget/verdicts/guardrails/scheduler); typecheck, lint, docs gates, and `check:pack` all green; per-file coverage floors held.

### Upgrade notes

- New config `review.enabled` / `review.dryRun` (on by default) / `review.dailyBudget` (100) / `review.batchSize` (10); no breaking changes; new tables are `CREATE IF NOT EXISTS`, built on open, no migration needed.
- dotnet-desktop resolves the plugin as an npm copy: after updating to 0.15.7 and restarting the profile, **hard-refresh the GUI page** (Ctrl+Shift+R).
- Acceptance during trial: no visible card change; verdict rows and daily rows are queryable in the store — `SELECT * FROM review_daily ORDER BY day DESC LIMIT 7`.
