<h3 id="cn-v0.15.11">v0.15.11 — 门失败的两副面孔：预算余量，与失败不再判死</h3>

试运行跑满两天后做了一次账本体检：19 条评审里 8 条是 `skip`，**8 条全部**是门失败。上一版据此把死因判为「路由/网关故障，与预算无关」——全量核对后这句话只对了一半：23 条门失败里 16 条确实是路由抖动（集中在几个分钟级窗口），**另有 7 条是 `stream finished with max-tokens`**，即 512 预算被推理 token 吃满后的截断，跟网络无关。本版把这两件事分开处理。

### 问题修复

- **门预算 512 → 1024，且截断不再吞掉有效 verdict**（@ZK-Andy，`7717d8d`）：两条轨（评审与提取）的门调用都提到 1024 token——门输出只有一个 verdict JSON，多出来的额度是留给推理模型的思考的。同时 `streamOnce` 不再替调用方决定「截断即失败」，改为把 finish 原因交回调用方：**门先解析已收到的文本，解析成功就照用**（JSON 往往在被切断之前就写完了），只有解析不出东西时才记 `gate-llm-failed: stream finished with max-tokens`。贵调用（改写、提取正文）保持严格——半截正文永不落盘。
- **失败行不再把条目判死**（@ZK-Andy，`7717d8d`）：`reviewStateOf` 此前把 `review_log` 里任意一行都算作「已评审」，于是 `gate-llm-failed` 这类**根本没评成**的行也让条目在 `staleDays` 内退出候选池。实测过它的复发：手工清掉 8 条失败行后，同一条下一轮又撞门失败、又被锁回去。现在六类失败原因（`gate-llm-failed*` / `evolve-llm-failed*` / `no-route` / `budget-exhausted` / 两个 parse 失败）不再算已评审，条目留队、下轮重试；门的有效拒绝（cheap-gate 给出的理由）与 keep/rewrite/quarantine 仍算完成。

### 新功能

- **评审设置全部 volatile，并新增 `review.staleDays`**（@ZK-Andy，`7717d8d`）：`review.enabled` / `dryRun` / `dailyBudget` / `batchSize` / `staleDays` 都标成宿主的 volatile 字段，调度器改为**每轮 drain 现读**设置——改动不用重挂载插件即生效。`staleDays`（默认 30）此前写死在代码里，现在可以在 profile patch 里调，例如试运行期先压到 7 天让条目更快回炉。
- 测试 333 → 337 例（截断但 verdict 完整仍计一次评审、截断且无可解析内容记失败、失败行不判死、设置热改在下一轮生效）；typecheck / lint / 文档门禁 / `check:pack` 全绿；覆盖率 96.14-89.74-100 守住水位线。

### 升级提示

- 无破坏性变更、无迁移；`review.*` 新键有默认值，旧 patch 照常工作。
- dotnet-desktop 是 npm 实体拷贝：更新到 0.15.11 后**重启 App** 即生效（`client/` 本版未动，无需硬刷）。
- 关 dry-run 的路径变短了：`review.dryRun` 已是 volatile，但**首次仍需本版发出去**才能让 desktop 拿到新代码；此后改 profile patch 即可，不必再改代码。

<h3 id="en-v0.15.11">v0.15.11 — the two faces of gate failure: budget headroom, and failures that no longer bench an item</h3>

After two days of trial mode we audited the ledger: of 19 reviews, 8 were `skip` — and **all 8 were gate failures**. The previous release read that as "route/gateway fault, nothing to do with budget", which the full ledger shows is only half true: of 23 gate failures, 16 are indeed route jitter (clustered in a few minute-long windows) and **7 are `stream finished with max-tokens`** — the 512 budget being eaten by a thinking model's reasoning, with no network involved. This release separates the two.

### Bug Fixes

- **Gate budget 512 → 1024, and a cut no longer discards a usable verdict** (@ZK-Andy, `7717d8d`): both tracks (review and extraction) now give the gate call 1024 tokens — the gate emits one verdict JSON, and the headroom is there for the reasoning that precedes it. `streamOnce` also stops deciding on the caller's behalf that a cut is fatal: it hands the finish reason back, and **the gate parses what it received first** (the JSON usually completes before the cut), ledgering `gate-llm-failed: stream finished with max-tokens` only when nothing parses. The expensive calls (rewrite, extraction payload) stay strict — half a body never lands.
- **A failed review no longer benches the item** (@ZK-Andy, `7717d8d`): `reviewStateOf` used to count any `review_log` row as "reviewed", so a `gate-llm-failed` row — a review that never happened — pushed the item out of the candidate pool for `staleDays`. We watched it recur: after clearing 8 failure rows by hand, the same item hit the gate again and was locked back. Six failure reasons (`gate-llm-failed*` / `evolve-llm-failed*` / `no-route` / `budget-exhausted` / both parse failures) no longer count as reviewed, so the item stays queued and retries next drain; a genuine gate refusal (a cheap-gate reason) and keep/rewrite/quarantine still count.

### Features

- **Every review setting is now volatile, plus `review.staleDays`** (@ZK-Andy, `7717d8d`): `review.enabled` / `dryRun` / `dailyBudget` / `batchSize` / `staleDays` are host-volatile fields, and the scheduler **re-reads them on every drain** — an edit takes effect without remounting the plugin. `staleDays` (default 30) was hardcoded; it is now a profile-patch knob, e.g. drop it to 7 during the trial so reviewed items come back sooner.
- Tests 333 → 337 (a cut gate with a complete verdict still counts as one review, a cut with nothing parseable is a failure, a failed review leaves the item queued, a live settings edit lands on the next drain); typecheck, lint, docs gates and `check:pack` all green; coverage 96.14-89.74-100 holds the floors.

### Upgrade notes

- No breaking changes and no migration; the new `review.*` keys carry defaults, so existing patches keep working.
- dotnet-desktop is an npm copy: update to 0.15.11 and **restart the app** (`client/` is untouched this release, no hard refresh needed).
- Turning dry-run off just got shorter: `review.dryRun` is volatile now, but desktop still needs this release once to get the code; after that it is a profile-patch edit, not a code change.
