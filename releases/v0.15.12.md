<h3 id="cn-v0.15.12">v0.15.12 — 直属调用的路由与档位：用默认模型的会话第一次真正能跑</h3>

一次账本体检暴露出整片失败：某个会话的提取调用 100% 失败、同一时段别的会话 100% 成功，而它们的 provider/model **完全相同**（`dsh-opencode-go` / `deepseek-v4.1-flash`）。追下去发现三件事叠在一起——插件把「显式选择」当成了「当前路由」、一条被折叠重构丢掉的档位纪律、以及一句把真因吞掉的失败文案。本版一次补齐，并把两条轨的直属调用收进同一个边界。

### 问题修复

- **路由改从宿主默认模型兜底，取不到就拒绝发送**（@ZK-Andy，`a85bbc7`）：`agent.options` 只承载**显式选择**——用默认模型的会话在那里什么都没有，而宿主把默认模型放在 `agentDefaultModel` 服务里（会话控制器与无头入口都从它取）。现在 `resolveCallRoute` 先读 `agent.options`、再读该服务（经 `ctx.get`，不进 inject 列表），两者皆无则**不发调用**：提取与评审都记一行 `no-route` 跳过，不再把空 provider 发给适配器。
- **恢复按能力推导推理档位**（@ZK-Andy，`a85bbc7`）：2026-09-24 的能力 ADR 给当时的共享边界 `llm-text.ts` 定过「按精确 provider/model 取最低开启档」；`dc1e679` 折叠重构删掉该边界后，取而代之的 `streamOnce` 没有恢复它，请求里从不带 `reasoningEffort`。现在两条轨都会调 `llm.resolveModelInfo` 取该模型声明的最低**开启**档，无元数据则省略该字段；能力查询失败在 provider I/O 之前暴露，不重试。
- **失败原文不再被吞**（@ZK-Andy，`a85bbc7`）：终止性的 `error` / `aborted` 一律抛出，文案带上宿主 `failure` 的 `code: message`——此前只留 `finish.kind`，账本里那句 `stream finished with error` 整整一天说不出死因。`max-tokens` 仍交调用方裁决（门在预算切断前可能已给出完整 verdict，这条语义保持不变）。
- **调度器生命周期两处收口**（@ZK-Andy，`a85bbc7`）：两个调度器的 disposer 此前在组装根被丢弃——重挂载（HMR、改配置）会留下第二个调度器、握着已被替换的 LLM 服务；现在挂到所属 fiber 的 `effect` 上。评审也不再从 `compaction/start` 与 `agent/disposed` 边界发起调用（那时手里只有刚销毁的会话身份），待评工作区留到下一个 turn 边界用活路由评。附带：提取失败行补记 `model` 列。

### 升级提示

- 无破坏性变更、无迁移。
- dotnet-desktop 是 npm 实体拷贝：更新到 0.15.12 后**重启 App** 即生效（`client/` 本版未动，无需硬刷）。
- 本版对**用默认模型的会话**是行为级修复：此前这类会话的提取轨只会记 `no-route`、评审环完全不工作，现在会真正调用。
- 失败行现在带宿主的错误 code/message——若还有失败，账本直接可读，不必再猜。
- 测试 337 → 362 例（新增 `llm-call` 边界 20 例：路由兜底、档位选择、失败文案、abort、能力查询失败；提取与评审调度各补路由用例）；typecheck / lint / 文档门禁 / `check:pack` 全绿。

<h3 id="en-v0.15.12">v0.15.12 — routes and reasoning effort for direct calls: default-model sessions finally run</h3>

A ledger audit surfaced wholesale failure: one session's extraction calls failed 100% of the time while another session's succeeded 100% in the same window — with **identical** provider/model (`dsh-opencode-go` / `deepseek-v4.1-flash`). Three things were stacked: the plugin treated an *explicit selection* as *the current route*, a reasoning-effort discipline was lost in a teardown refactor, and the failure text named no cause. This release fixes all three and moves both tracks' direct calls behind one boundary.

### Bug Fixes

- **Routes now fall back to the host default model, and a call with no route is refused** (@ZK-Andy, `a85bbc7`): `agent.options` carries an *explicit* selection only — a session on the default model has nothing there, while the host keeps that selection in its `agentDefaultModel` service (the session controller and the headless entry point both read it). `resolveCallRoute` now reads `agent.options` first and that service second (through `ctx.get`, never an inject list), and **sends nothing** when neither has one: extraction and review each ledger a `no-route` skip instead of streaming an empty provider into the adapter.
- **Capability-derived reasoning effort restored** (@ZK-Andy, `a85bbc7`): the 2026-09-24 capability note gave the then-shared `llm-text.ts` boundary the rule "take the lowest enabled effort the exact provider/model advertises"; the `dc1e679` teardown deleted that boundary, and the `streamOnce` that replaced it never restored the rule, so requests carried no `reasoningEffort` at all. Both tracks now resolve it through `llm.resolveModelInfo`, omit the field when the model publishes no metadata, and let a capability lookup failure surface before any provider I/O — never retried.
- **Failure text is no longer swallowed** (@ZK-Andy, `a85bbc7`): terminal `error` / `aborted` finishes always throw, carrying the host `failure`'s `code: message`. Only `finish.kind` used to survive, which is why one line of `stream finished with error` named no cause for a full day. `max-tokens` still goes back to the caller (a gate can complete its verdict before the cut; that semantic is unchanged).
- **Two scheduler-lifecycle gaps closed** (@ZK-Andy, `a85bbc7`): both schedulers' disposers were discarded at the assembly root, so a remount (HMR, a config edit) left a second scheduler holding an LLM service that had already been replaced; they now ride the owning fiber's `effect`. Review also stops draining from the `compaction/start` and `agent/disposed` boundaries — at those moments the only identity available is the session that just died — and leaves the pending workspace to the next turn boundary with a live route. Extraction failure rows now record the `model` column too.

### Upgrade notes

- No breaking changes, no migration.
- dotnet-desktop is an npm copy: update to 0.15.12 and **restart the app** (`client/` is untouched, no hard refresh needed).
- This is a behavior-level fix for **default-model sessions**: their extraction track previously only ever ledgered `no-route`, and their review track never ran at all.
- Failure rows now carry the host's error code and message, so any remaining failure is readable straight from the ledger.
- Tests 337 → 362 (20 new for the `llm-call` boundary — route fallback, effort selection, failure text, abort, capability-lookup failure — plus route cases in both schedulers); typecheck, lint, docs gates and `check:pack` all green.
