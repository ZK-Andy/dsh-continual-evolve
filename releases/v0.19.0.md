<h3 id="cn-v0.19.0">新功能</h3>

- **观测三件：代际自检、注入账本、检索评测（`e60f29f`，@ZK-Andy）**。插件第一次能用数字回答三件事。① **代际自检**（`services/build-identity.ts`）：进程导入时对自身入口文件取 sha1（`codeGeneration`），查询时重读盘面（`diskGeneration`），两者不同即 `restartRequired`——卡片首行显示「运行代 / 盘面代」，不一致标红并写明需重启，`plugin_log` 每次 mount 落一条 `build-identity`。任一侧不可读一律判「不欠重启」：观测不可用绝不阻塞注入。② **注入账本**（`data/injection-log.ts`）：section 每会话只构建一次，因此每会话一行，记录索引点名的 id 与估算 token（30 天随其他账本裁剪）；读侧按「该 id 的 `memory_usage.last_used_at` ≥ 注入时刻」算近 7 天「注入 N / 被读 M（X%）」转化率，卡片显示。局限写在明处：它答的是「有没有被读」，不是「回答有没有用上」。③ **检索评测**（`scripts/eval-recall.ts`）：`npm run eval:recall` 在临时库播种 fixture、跑固定查询、报 hit@1 与 MRR；空 fixture 按设计退出 1。
- **注入预算改按 token，超了降级而不是丢掉（`e60f29f`）**。旧的 `memoryIndex.maxChars` 是字符预算，中文实际是 1.2–1.5 token/字，所谓「6k」一直给的是 7000–9000 token。现在预算单位是 token（CJK 感知估算，默认 6000），超预算分三档降级：完整钩子行 → `- [id]` 行 → `（其余 N 条未展开…）` 计数行——被预算裁掉的记忆仍能 `evolve_read` 找回，而不是从上下文里消失。旧 `maxChars` 只被读一次并折算入库，不留第二读点。
- **提取提案的确定性预筛（`e60f29f`）**。正文与既有 active 记忆全等的 `duplicate`、字段没变的 `no-change` 提案不再进写门禁——它们此前会白改一次 `updated_at`、推进评审队列、在账本里算作「已应用」。跳过原因落 `extraction_log.skip_reason`（`pre-screen: duplicate×N`）。`delete` 与短禁令不受影响——「正文太短」那条规则试过，因误杀真实提案被移除。
- **记忆可带「不适用条件」`notWhen`（`e60f29f`）**。新增一列（≤200 字），随钩子渲染成「（不适用：…）」并在卡片打标记，`evolve_write` 与提取提案都可携带。**只做提示，不参与检索过滤**——负路由需要条件匹配引擎，属于下一批。

### 问题修复

- **中文长查询零命中（`e60f29f`）**：`"什么时候可以 publish"` 整段被当成一个关键词，要求标题里出现「什么时候可以」这个 7 字连续片段，于是检索返回空。现在 CJK 长片段按 3 字窗口展开，窗口内 OR、词组间 AND。
- **AND 语义吃掉自然语言问句（`e60f29f`）**：词组凑不齐时整句零命中。增加第二趟——严格路全空且不止一个词时退回 OR 重试。
- **索引顺序不确定（`e60f29f`）**：`MEMORIES_ORDER` 缺 tiebreak，同 `updated_at` 的行顺序由 SQLite 自定，破坏「会话内字节稳定」这一 prompt-cache 契约。补 `, id ASC`。
- **governance 工作流 shell 注入（`8b94e16`）**：issue 正文经 `${{ }}` 插进 shell，代码围栏里的反引号让该步恒 exit 2——这项校验此前从未真正执行。现改为 `scripts/governance-check.ts` 纯函数校验、事件负载走环境变量，恒退出 0。

<h3 id="en-v0.19.0">Features</h3>

- **Three observability additions (`e60f29f`, @ZK-Andy)**. The plugin can now answer three questions with data. ① **Build identity** (`services/build-identity.ts`): the process hashes its own entry file at import (`codeGeneration`) and re-reads it on demand (`diskGeneration`); they differ ⇒ `restartRequired`. The card's first line shows both and turns red with "restart the host"; `plugin_log` carries the same reading as a `build-identity` row. When either side is unreadable it reports "no restart owed" — observability never blocks injection. ② **Injection ledger** (`data/injection-log.ts`): the section is built once per session, so the ledger holds one row per session (ids named, estimated tokens, pruned with the other ledgers at 30 days); the card shows a 7-day "injected N / read M (X%)" conversion, where *read* means the body was served after the injection that named it. Its limit is stated, not hidden: it answers "was it read", never "did the answer use it". ③ **Recall evaluation** (`scripts/eval-recall.ts`): `npm run eval:recall` seeds a throwaway store from a fixture, runs fixed queries and reports hit@1 and MRR; an empty fixture is red by design.
- **The injection budget is tokens now, and overflow degrades instead of dropping (`e60f29f`)**. The old `memoryIndex.maxChars` was a character cap while Chinese costs ~1.2–1.5 tokens per character, so "6k" actually shipped 7000–9000 tokens. The budget is now tokens (CJK-aware estimate, default 6000) and an index that does not fit degrades in tiers: full hook lines → `- [id]`-only lines → a `（其余 N 条未展开…）` counter. A memory the budget could not afford stays reachable through `evolve_read` instead of vanishing. The legacy key is read once, converted, and never read again.
- **Deterministic pre-screen for extraction proposals (`e60f29f`)**. Proposals that duplicate an existing body (`duplicate`) or change nothing (`no-change`) no longer reach the write gate — they used to bump `updated_at`, move the review queue and count as "applied". The reason lands in `extraction_log.skip_reason` (`pre-screen: duplicate×N`). Deletes and short prohibitions are untouched: a "too short to be a rule" rule was tried and removed after it misfired on real proposals.
- **Memories can carry a caveat, `notWhen` (`e60f29f`)**. A new column (≤200 chars) rendered next to the hook as "（不适用：…）" and badged on the card; both `evolve_write` and extraction proposals may set it. Presentation only — retrieval never filters on it.

### Bug Fixes

- **Chinese long queries returned nothing (`e60f29f`)**: `"什么时候可以 publish"` was treated as one keyword, requiring the literal 7-character run in the title. CJK fragments now expand into 3-character windows, OR-ed inside a token and AND-combined across tokens.
- **AND semantics swallowed natural-language questions (`e60f29f`)**: when the token groups could not all match, the whole query returned nothing. A second pass now retries with OR when the strict pass is empty and the query has more than one token.
- **Non-deterministic index order (`e60f29f`)**: `MEMORIES_ORDER` had no tiebreak, so rows sharing `updated_at` came back in SQLite's own order — breaking the byte-stable-per-session contract the prompt cache relies on. Added `, id ASC`.
- **governance workflow shell injection (`8b94e16`)**: the issue body was interpolated into a shell via `${{ }}`, and backticks in code fences made that step exit 2 every time — the check had never actually run. Validation moved into `scripts/governance-check.ts` with the payload passed as an environment variable; the step always exits 0.
