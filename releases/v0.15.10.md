<h3 id="cn-v0.15.10">v0.15.10 — 让试运行看得见：技能按分区判、拟改稿留档</h3>

试运行跑了一天，暴露两处偏差，都在「人工评估」这一侧：一条**项目级**技能被按全局口径判了隔离；而判改写/隔离的行只留下「为什么改」，看不到「改成什么样」。本版把这两处补上。

### 新功能

- **技能评审按分区判**（@ZK-Andy，`f43d0ed`）：项目分区（`scope=project`）的技能只判①触发精度②正文可执行完备③同分区不重复——绑本仓库的路径、门禁命令、流程卡是项目技能的设计意图，不再算缺陷；「跨项目可复用」只对 `scope=global` 判，「放错家」重新定义为「全局分区却绑某仓库」。gate 与 evolve 两侧 prompt 都带 `scope=project|global` 行，模型不必猜自己在评哪一档。此前 `ts-standards` 因「绑单一仓库」被判隔离，正是这条口径造成的误伤。
- **试运行留拟改稿**（@ZK-Andy，`f43d0ed`）：`review_log` 增 `proposed` 列（旧库 ALTER 迁移）。非落盘的两条路径——改写、以及「幅度超限转隔离」——把模型给出的 `title` / `description` / `body` / `corrects` 收进该列（只收实际给出的字段）；落盘行不写（改动本身就在记录里），模型未给正文时该列为 NULL。查法：`SELECT item_id, proposed FROM review_log WHERE proposed IS NOT NULL`。
- 测试 330 → 333 例（prompt 渲染 `scope=`、dry-run 行带拟稿、隔离行无拟稿、`proposed` 往返与旧库迁移），typecheck/lint/文档门禁/`check:pack` 全绿；覆盖率门禁全文件达标。

### 其他改动

- 决策记录（仅文档，无需动作）：提取门失败首样本坐实为**路由/网关级故障**（`stream finished with error`，且发生在 flash 上），因此**门预算维持 512，且不做重试**——代理与网关不稳定的前提下重试只是再烧一遍自己的 token 与时间；失败即 fail-open 并把原文记进 `cheap_error`。

### 升级提示

- 无配置变更、无破坏性变更；新列 `proposed` 旧库打开即迁，无需手动迁移。
- dotnet-desktop 是 npm 实体拷贝：更新到 0.15.10 后**重启 App** 即生效（`client/` 本版未动，无需硬刷）。
- 关 dry-run 之前建议先读几行 `proposed`：那是「它打算改成什么样」，比理由更值得过目。

<h3 id="en-v0.15.10">v0.15.10 — making the trial legible: skills judged by scope, declined rewrites kept</h3>

A day of trial mode exposed two biases, both on the human-review side: a **project-scoped** skill was verdicted with the global rubric, and rewrite/quarantine rows kept only *why* the loop would change an item — never *into what*. This release closes both.

### Features

- **Skill verdicts are scope-aware** (@ZK-Andy, `f43d0ed`): a `scope=project` skill is judged on ①trigger precision ②executability ③in-project non-duplication only — binding this repo's paths, gate commands and workflow cards is what a project skill is for, not a defect. The cross-project reuse test applies to `scope=global` alone, and mis-homing is redefined as "a global row bound to one repo". Both the gate and evolve prompts carry a `scope=project|global` line, so the model never has to guess which rubric applies. `ts-standards` was quarantined for being repo-bound — that verdict came from the old blanket rule.
- **Trial mode keeps the rewrite it declines** (@ZK-Andy, `f43d0ed`): `review_log` gains a `proposed` column (old stores migrate by ALTER). The two non-landing paths — a rewrite, and an oversized rewrite degraded to quarantine — store the `title`/`description`/`body`/`corrects` the model supplied (only the fields it actually gave); landed rows stay lean because the change itself is in the record, and the column is NULL when the model proposed no text. Query: `SELECT item_id, proposed FROM review_log WHERE proposed IS NOT NULL`.
- Tests 330 → 333 (prompts rendering `scope=`, a dry-run row carrying the proposal, a quarantine row carrying none, `proposed` round-trip plus the legacy-store migration); typecheck, lint, docs gates and `check:pack` all green; per-file coverage floors held.

### Chores

- Decision records (docs only, no action needed): the first failed-gate sample proved a **route/gateway fault** (`stream finished with error`, on flash), so the gate keeps its 512 budget and gets **no retry** — with an unstable proxy and gateway a retry only burns our own tokens and time again; the gate fails open and ledgers the error text in `cheap_error`.

### Upgrade notes

- No config or breaking changes; the new `proposed` column migrates on first open.
- dotnet-desktop is an npm copy: update to 0.15.10 and **restart the app** (`client/` is untouched this release, no hard refresh needed).
- Before turning dry-run off, read a few `proposed` rows: that is what the loop would actually write, and it deserves a look more than the reasons do.
