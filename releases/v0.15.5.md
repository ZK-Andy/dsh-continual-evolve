<h3 id="cn-v0.15.5">v0.15.5 — 技能接线 S1：项目技能库 + 手动搬家</h3>

提取轨稳定后，自进化下阶段的第一步：10-04 终极收敛时拆掉的技能整套，以最小手动形态回来——可复用的操作规程有了沉淀处，`skill` 工具重启后即可发现调用。拍板语义先行：创建只能是项目，全局只接受手动搬家（无晋升机制）；库是唯一真相，文件是只读投影。

### 新功能

- **`skill_write` / `skill_read`**（@ZK-Andy，`f2f51ad`）：`skill_write`（create/update/delete + 手动搬到全局）走与记忆同一套门禁纪律（短横线 id 含 CJK hash 兜底、secret 正则、64KB 上限），另加跨范围纪律——全局已存在同名即拒绝（内容相同提示直接调用），正文完全相同即拒绝（指向已有的那条）。`skill_read` 按 id 取正文、按关键词检索项目与全局技能，同名时项目遮蔽全局。本期提取轨不产技能提案。
- **库是真相，文件是投影**（同上）：同库新表 `skills` + `skills_fts` + `skill_log`（before/after 全文 + 文件投影告警）；落库成功后插件代码把 active 行物化为 `SKILL.md`（项目技能进本工作区 `.agents/skills/<id>/`，全局进 `~/.dsh/skills/<id>/`，原子 tmp+rename，frontmatter `name/description` 携带路由 hint）。模型禁直写文件，文件头打生成标记；巡检发现缺失/漂移按库重写、无主托管文件删除、手改文件保留并告警；被隔离技能的物化文件一并撤下。
- **手动搬家**（同上）：用户明确说到处用才执行一次——全局建行 + 物化，同时项目行归档 + 项目文件删除，永远只有一份 active。
- **卡片技能区**（同上）：只读技能列表 + 按 id 预览（项目技能 + 可见全局技能，全局行打标记），预览同记忆；`mostRecentlyActiveWorkspace` 计入技能写入，技能-only 分区照常成为卡片默认。6k 记忆注入预算不动。
- 测试 199 → 258 例（新增 59 个技能回归：门禁/落库/物化/搬家/巡检/卡片），typecheck/lint/文档门禁/`check:pack` 全绿；覆盖率 statements 96 / branches 90 / functions 100。

### 升级提示

- 无配置变更、无破坏性变更、无库迁移（新表 `CREATE IF NOT EXISTS`，旧库打开即建）。
- dotnet-desktop 是 npm 实体拷贝：更新到 0.15.5 并重启 profile 后，**请硬刷新 GUI 页面**（Ctrl+Shift+R）。
- 技能 V1 重启生效：`skill_write` 落盘后需重启宿主，`skill` 工具方可发现。
- 验收：实体拷贝 `package.json` 版本为 0.15.5；建一条测试技能→本工作区 `.agents/skills/<id>/SKILL.md` 落盘且带生成标记；卡片技能区可见并可预览；手动搬家后全局生效、项目侧归档撤文件。

<h3 id="en-v0.15.5">v0.15.5 — skill wiring S1: project skill store + manual move to global</h3>

With the extraction track stable, the first step of the next self-evolution phase: the skill subsystem removed in the 10-04 teardown returns in its minimal manual form — reusable procedures finally have somewhere to sediment, discoverable by the `skill` tool after a restart. Semantics first: creation is project-only, global accepts only an explicit manual move (no promotion mechanism); the database is the sole source of truth, files are a read-only projection.

### Features

- **`skill_write` / `skill_read`** (@ZK-Andy, `f2f51ad`): `skill_write` (create/update/delete + manual move-to-global) passes the same gate discipline as memories (kebab ids with CJK hash fallback, secret screening, 64KB cap), plus cross-scope discipline — an existing same-named global skill rejects the write (identical content points at calling it directly), byte-identical bodies reject (pointing at the existing row). `skill_read` fetches skill bodies by id and searches project plus global skills, project shadowing global on name collisions. Extraction produces no skill proposals in this release.
- **Store is truth, files are projection** (same): new in-database tables `skills` + `skills_fts` + `skill_log` (before/after snapshots plus file-projection warnings); after a successful landing the plugin code materializes active rows as `SKILL.md` (project skills into the workspace's own `.agents/skills/<id>/`, global ones into `~/.dsh/skills/<id>/`, atomic tmp+rename, frontmatter `name/description` carrying a routing hint). Models must not write the files directly; every file carries a generated marker — patrol rewrites missing/drifted files from the store, removes orphan managed files, and leaves hand-written files alone with a warning; a quarantined skill's materialized file is removed with it.
- **Manual move** (same): only on the user's explicit "use it everywhere" — one global row plus materialization, while the project row archives and its file is removed. Exactly one active copy, always.
- **Card skills section** (same): read-only skill list plus per-id preview (project skills plus visible global skills, global rows badged), previewed like memories; `mostRecentlyActiveWorkspace` now counts skill writes, so skills-only partitions become the card default normally. The 6k memory injection budget is untouched.
- Tests 199 → 258 (59 new skill regressions: gates/landing/materialization/moves/patrol/card); typecheck, lint, docs gates, and `check:pack` all green; coverage statements 96 / branches 90 / functions 100.

### Upgrade notes

- No config changes, no breaking changes, no store migration (new tables are `CREATE IF NOT EXISTS`, built on open).
- dotnet-desktop resolves the plugin as an npm copy: after updating to 0.15.5 and restarting the profile, **hard-refresh the GUI page** (Ctrl+Shift+R).
- Skills are restart-activated in V1: after `skill_write` lands, restart the host before the `skill` tool can discover it.
- Acceptance: the installed copy's `package.json` reads 0.15.5; creating a test skill lands `<workspace>/.agents/skills/<id>/SKILL.md` with the generated marker; the card's skills section lists it with preview; after the manual move the global copy is live and the project side is archived with its file removed.
