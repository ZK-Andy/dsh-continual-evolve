<h3 id="cn-v0.14.1">v0.14.1 — 卡片工作区选择器对齐 ZCode + 刷新按钮断线修复</h3>

### 新功能

- **工作区选择器真对齐 ZCode**（@ZK-Andy）：目录改接宿主的工作区注册表 `ctx.workspaceRegistry`（与 GUI 工作区选择器同源；不可用时回退 `storages/workspace.json`，再回退本进程服务过的根），并把 v0.14 的一排 chips 换成 ZCode 式**下拉作用域选择器**——前导标记 + 当前工作区名 + chevron，`role="menu"` / `menuitemradio` + `aria-checked`，第二行显示根路径（注册表允许重名标题），选中 / Escape / 点击外部关闭。
- **为什么换**（@ZK-Andy）：chips 只在已知工作区 >1 时渲染，而 dotnet-desktop 日常只服务一个工作区——整块选择 UI 不渲染、无占位无禁用态，"工作区切换"看起来根本没实现。现在**单个工作区也照常渲染**。
- **列表与围栏分开**（@ZK-Andy）：卡片只列**有记忆库**的工作区（ZCode 记忆选项卡同规则：plain 目录、拒 symlink）；API 的读围栏则覆盖目录里的每个根——列表→读取之间被删掉的库降级成空态，而不是 404。

### 问题修复

- **「刷新」按钮断线修复**（@ZK-Andy）：v0.14.0 重塑卡片时把刷新动作抽成局部函数却未传给文件列表，按钮可见但点击无反应，快照挂载后也不再重载；现已接回并补行为级回归测试。
- **`client/` 纳入 lint 范围**（@ZK-Andy）：此前手写 bundle 既不在 lint 也不在 tsc 内，这条断线因此漏网。

### 其他改动

- 测试 80 → 91（8 文件）：新增工作区目录 7 例、宿主注册表接线 1 例、客户端选择器 2 例。决策见 ADR `2026-10-05-zcode-workspace-switcher` 与 `2026-10-05-card-refresh-unwired`。

### 升级提示

- dotnet-desktop 是 npm 实体拷贝：更新到 0.14.1 并重启 profile 后，在官方插件管理本插件页验收——①工作区下拉可切换（列表只显示有记忆库的工作区，本机当前为 `work` 与 `dotnet-deepseek-harness-desktop`）②「刷新」按钮点击后文件列表真的重载。
- `memoryIndex.*` 与 `memoryCard.enabled` 配置与行为无任何变化。

<h3 id="en-v0.14.1">v0.14.1 — ZCode-aligned workspace selector + refresh-button fix</h3>

### Features

- **Workspace selector aligned with ZCode** (@ZK-Andy): the catalogue now comes from the host's workspace registry, `ctx.workspaceRegistry` (the same durable records the workspace picker renders; falling back to `storages/workspace.json` and then to the roots this process served), and v0.14's chip row became ZCode's **dropdown scope selector** — leading marker + current workspace label + chevron, `role="menu"` / `menuitemradio` with `aria-checked`, the root path on the second line (the registry allows duplicate titles), closing on select / Escape / outside click.
- **Why** (@ZK-Andy): the chip row only rendered when more than one workspace was known, and dotnet-desktop usually serves a single workspace — so the whole control rendered nothing, with no placeholder or disabled state, and switching read as unimplemented. It now renders **with a single workspace too**.
- **Listing and fence separated** (@ZK-Andy): the card lists only workspaces **with a memory store** (ZCode's rule: a plain directory, symlinks rejected), while the read API's fence covers every catalogued root — a store deleted between listing and read degrades to the empty state instead of a 404.

### Bug Fixes

- **Refresh button rewired** (@ZK-Andy): the v0.14.0 reshape extracted the refresh action but never handed it to the file list, so the button rendered inert and the snapshot never re-loaded after mount; it is wired again with a behavioral regression test.
- **`client/` joins the lint scope** (@ZK-Andy): the hand-written bundle sat outside both lint and tsc, which is how the unwired callback slipped through.

### Chores

- Tests 80 → 91 (8 files): 7 catalogue cases, 1 host-registry wiring case, 2 client selector cases. Decisions: ADRs `2026-10-05-zcode-workspace-switcher` and `2026-10-05-card-refresh-unwired`.

### Upgrade notes

- dotnet-desktop installs an npm copy: update to 0.14.1, restart the profile, and open the plugin's page in the official plugin manager to review — ① the workspace dropdown switching works (only workspaces with a memory store are listed; on this machine `work` and `dotnet-deepseek-harness-desktop`) ② the refresh button actually reloading the file list.
- `memoryIndex.*` and `memoryCard.enabled` configuration and behavior are unchanged.
