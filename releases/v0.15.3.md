<h3 id="cn-v0.15.3">v0.15.3 — 提取账本记下失败、折叠噪声</h3>

两项都是提取轨的**可审计性**：一次失败不再无从回查，一片"跳过"不再淹没信号。起点是 2026-10-07 用真轨迹对账——判定一条没错，问题都在账本这一侧。

### 新功能

- **空转跳过合并为一行计数**（@ZK-Andy，`4d718b4`）：一个回合没有新的真实用户发言时，提取轨会机械跳过并记账。自动续跑与子代理回传的回合让这类行**每轮写一行**——2026-10-07 当天 22 行账本里 16 行是同一个 `no-user-prose` 事实。现在空转型跳过（`no-user-prose` / `no-new-events`）**同会话连续发生时合并为一行**：新增 `occurrences` 列累计唤醒次数，`ts` 刷新为最新一次（"最近活动"判据不变）。中间只要落了任何一行——模型判定、应用批次、不同原因、别的会话——就另起一行，等价于"同一游标位置"。故障型跳过（`no-route`/`no-surface`/`no-workspace`）与全部失败**保持逐次成行**：持续故障该留时间线，而不是被压成一个计数器。

### 问题修复

- **解析失败保留模型回答原文**（@ZK-Andy，`6454281`）：模型回答不是合法 JSON 时，运行记为失败且游标不动（下次触发重试），但失败行原先**不留任何证据**——`extraction_log.files` 恒空，事后只能靠猜。现在把回答原文前 ~2KB 写进该行的 `files`，`unparseable output` 可回查。

### 升级提示

- 无配置变更、无破坏性变更。账本新增的 `occurrences` 列在插件首次打开既有库时自动 `ALTER TABLE` 补齐，历史行回填 `1`（已在真库副本上验证：47 行零丢失、三次重复折成一行、故障型两连发仍两行）。
- dotnet-desktop 是 npm 实体拷贝：更新到 0.15.3 并重启 profile 后，**请硬刷新 GUI 页面**（Ctrl+Shift+R）。
- 验收（机器侧为主，无需目检）：实体拷贝 `package.json` 版本为 0.15.3；正常聊几轮后账本里连续空转轮次应收敛为一行且 `occurrences` 增长，而失败行带 `files` 原文。

<h3 id="en-v0.15.3">v0.15.3 — the extraction ledger keeps failures, folds noise</h3>

Both changes are about the extraction track's **auditability**: a failed run stops being undiagnosable after the fact, and a wall of skips stops drowning the signal. The driver was a 2026-10-07 reconciliation against raw session events — every verdict was right; the problems were all on the ledger side.

### Features

- **Quiet-turn skips fold into one counted row** (@ZK-Andy, `4d718b4`): when a turn adds no real user prose, extraction skips it mechanically and ledgers that fact. Autonomous continuation rounds and subagent hand-backs made it write **a row per turn** — 16 of that day's 22 ledger rows were the same `no-user-prose` fact. Quiet-turn skips (`no-user-prose` / `no-new-events`) now **coalesce into one row while they repeat consecutively within one session**: the new `occurrences` column counts the wake-ups and `ts` moves to the newest one (so the "most recently active" signal is unchanged). Anything landing in between — a model decision, an applied batch, a different reason, another session — starts a new row, which is exactly "the same cursor position". Fault-shaped skips (`no-route`/`no-surface`/`no-workspace`) and every failure **stay one row per occurrence**: a persistent fault deserves a timeline, not a counter.

### Bug Fixes

- **A failed parse keeps the model's raw answer** (@ZK-Andy, `6454281`): when the model's answer is not valid JSON the run is ledgered as failed and the cursor stays put (the next trigger retries), but the failure row carried **no evidence at all** — `extraction_log.files` was always empty, leaving `unparseable output` undiagnosable after the fact. The first ~2KB of the answer now ride in that row's `files`.

### Upgrade notes

- No config or breaking changes. The ledger's new `occurrences` column is added by `ALTER TABLE` the first time the plugin opens an existing store, with historical rows backfilled to `1` (verified against a copy of the live library: 47 rows, none lost, three repeats folded into one, two consecutive fault skips still two rows).
- dotnet-desktop ships an npm copy: after updating to 0.15.3 and restarting the profile, **hard-refresh the GUI page** (Ctrl+Shift+R).
- Acceptance (machine-side; no visual check needed): the npm copy's `package.json` reads 0.15.3; after a few ordinary turns, consecutive quiet turns in the ledger collapse into one row whose `occurrences` grows, while a failure row carries the raw answer in `files`.
