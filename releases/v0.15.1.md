<h3 id="cn-v0.15.1">v0.15.1 — 提取调度按会话隔离、检索兜底、发布产物门禁</h3>

这一版修掉 v0.15.0 在桌面端验收中实测暴露的两个问题（@ZK-Andy）：**提取轨一次都没跑成**，以及**多关键词检索恒返回空**；同时给发布链路补上一道产物门禁。

### 问题修复

- **提取调度改按会话隔离**（@ZK-Andy，`0e1b4de`）：v0.15.0 的调度器是**插件单例**——一个 `pending` 槽、一个 `running` 标志、一个全局 10 分钟计时器，而它的游标却早已按会话分区。后果是任何 agent 的 `agent/turn-stopping` 都会覆盖槽位并 `clearTimeout` 重置计时器，内部 agent 的过滤又排在运行入口（太晚）。实测：另一个工作区的 10 个子代理把主会话的边界顶掉并推迟 36 分钟；同一会话连续四轮对话把计时器重置四次、**零次触发**——提取从未真正运行。现在调度状态按会话分槽（每会话一个边界 + 一个在飞运行），运行中只保留该会话的最新边界、完成时自动 drain；内部 agent 在调度入口即被过滤（不占槽、不留账本墓碑）；**空闲去抖连同 `memoryIndex.debounceMin` 一并删除**，改为轮级调度。这正是 ZCode 记忆提取的 per-runtime scheduler 形态。
- **检索按关键词 AND，带 LIKE 兜底**（@ZK-Andy，`8179d6a`）：`memory_read` 原先把整串查询当作一个 FTS5 短语，因此 `中文 交接` 这类由短词组成的多关键词查询恒返回空。现在按空白分词、词间取 AND：全部词 ≥3 字符走 trigram 索引，任一短词或 FTS 未命中时回退字面子串匹配（`\ % _` 按字面转义）。

### 变更

- **发布产物门禁**（@ZK-Andy，`d471429`）：`build` 在编译前清理 `lib/`；`prepack` 与 CI 新增 `check:pack`，校验孤儿产物、缺失配对与 `files` 白名单空匹配。0.15.0 的包里就带着 4 个已退役模块的构建产物，今后不会再有。

### 升级提示

- **配置破坏性变更**：`memoryIndex.debounceMin` 已移除；`memoryIndex.extraction` 仍是提取的唯一开关。旧配置里的该键会被忽略。
- **行为变化**：提取不再等"空闲 10 分钟"，而是每轮结束即调度——有增量才调用模型；空增量、无真实用户文本、当轮已有显式写入等仍照旧机械跳过并记账。
- dotnet-desktop 是 npm 实体拷贝：更新到 0.15.1 并重启 profile 后，**请硬刷新 GUI 页面**（Ctrl+Shift+R）。
- 验收：① 注入索引正常出现 ② "记住……"走 `memory_write` 落库 ③ 卡片列表与内容预览正常 ④ **提取轨开始产出**——`extraction_log` 出现 `trigger='turn-debounce'` 记录、`state` 出现 `seq:<会话>` 游标，且多个工作区不再互相推迟。

<h3 id="en-v0.15.1">v0.15.1 — Per-session extraction scheduling, search fallback, pack-contents gate</h3>

Two problems measured on the desktop host during the v0.15.0 acceptance (@ZK-Andy) are fixed here: **extraction never actually ran**, and **multi-keyword search always came back empty** — plus one new gate on the publish path.

### Bug Fixes

- **Extraction scheduling is now per session** (@ZK-Andy, `0e1b4de`): the v0.15.0 scheduler was a plugin singleton — one `pending` slot, one `running` flag, one global 10-minute timer — while its cursor was already partitioned per session. Any agent's `agent/turn-stopping` could therefore overwrite the slot and `clearTimeout` the timer, and internal agents were filtered only inside the run (too late). Measured: ten subagents of another workspace displaced the main session's boundary for 36 minutes, and four consecutive turns in one session reset the timer four times with **zero fires** — extraction never ran. Scheduling state is now per session (one boundary plus one in-flight run each): a run in flight keeps only that session's newest boundary and drains it on completion, internal agents are filtered at the scheduling entry (no slot, no ledger tombstones), and **the idle debounce and its `memoryIndex.debounceMin` key are gone** in favour of turn-level scheduling. This is the shape of ZCode's per-runtime memory-extraction scheduler.
- **Search AND-combines keywords with a LIKE fallback** (@ZK-Andy, `8179d6a`): `memory_read` treated the whole query as a single FTS5 phrase, so keyword pairs made of short terms (`中文 交接`) always returned nothing. Queries are now split on whitespace and AND-combined: all terms ≥3 chars go through the trigram index, and any short term — or an FTS miss — falls back to literal substring matching (`\ % _` matched literally).

### Changes

- **Pack-contents gate** (@ZK-Andy, `d471429`): `build` cleans `lib/` before compiling, and `prepack` plus CI run the new `check:pack` (orphan artifacts, missing pairs, `files` globs matching nothing). The 0.15.0 tarball carried four build outputs of retired modules; that cannot happen again.

### Upgrade notes

- **Breaking config change**: `memoryIndex.debounceMin` is removed; `memoryIndex.extraction` remains the single switch for extraction. The old key is ignored if present.
- **Behaviour change**: extraction no longer waits for a 10-minute idle window — every turn schedules its session's boundary, and a model call happens only when there is an increment. Empty increments, turns without real user prose, and turns that already carried an explicit write are still mechanically skipped and ledgered.
- dotnet-desktop ships an npm copy: after updating to 0.15.1 and restarting the profile, **hard-refresh the GUI page** (Ctrl+Shift+R).
- Acceptance: ① the injected index appears ② "remember …" lands via `memory_write` ③ the card lists workspaces and previews bodies ④ **extraction actually produces** — `extraction_log` gains `trigger='turn-debounce'` rows, `state` gains a `seq:<session>` cursor, and workspaces no longer delay each other.
