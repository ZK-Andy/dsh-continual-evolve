本版是一次**结构收敛**：把架构漂移按四批收掉——退役面纯删、卡片归档区与列表行同形、投影规则与建表 DDL 归位、规范与门禁对齐。对外只有一处可见变化（归档区的呈现），其余是内部形状收敛：存储语义、注入内容与评审口径不变。948 测试 / 77 文件、22 道门禁红绿俱验、CI 全绿。

<h3 id="cn-v0.19.3">移除与停用</h3>

- **评测任务集退役面纯删（`7be8bea`，@ZK-Andy）**：`services/eval-taskset.ts` 及其测试删除——合成四臂下线后它生产零引用，只有自己的测试引用它，却随包发布。`store.writeEvalCases` 与 `data/eval-cases.ts` 的写入面一并下线（表形状与 30 天裁剪保留），只服务该写入面的零消费者常量（`EVAL_*_CHAR_CAP`、`EVAL_LAST_FOUR_ARM_KEY` 等）与 `redactText` 同步删除。`files` 白名单移除仓内保留、包内无读者的 `evals/tasks` 与 `evals/baseline`。理由见 ADR `2026-10-20-architecture-drift-remediation`。

<h3 id="cn-v0.19.3-fixes">问题修复</h3>

- **卡片归档区与列表行同形（`7be8bea`，@ZK-Andy）**：归档行改走列表行渲染器的只读分支（徽标、展开、预览动作全关），`archive_reason` 的五个取值进卡片内联字典（zh/en），中文界面不再裸出英文枚举。此前同一份记忆在卡片里有两套形态。
- **被提级的归档行给出全局活副本指针（`7be8bea`，@ZK-Andy）**：仅当 `archive_reason = promoted-source` 且全局活行的 `origin_workspace` 恰为本工作区时给 `globalCopyId`，徽标标「内容在全局（id）」并保留 id 段供人工对账。分区隔离下别的分区同 id 的全局行不是这条记忆的活副本，所以指针不乱指。提级产生的行不再被读成「内容被撤销」。

<h3 id="cn-v0.19.3-other">其他改动</h3>

- **投影规则收成一处（`7be8bea`，@ZK-Andy）**：「本地行遮蔽全局同 id 行」只在 `data/memory-reads.ts` 的 `globalOnly` 定义一次，注入、检索、卡片 `mergedVisible` 三个读者各传自己的候选集。卡片与注入／检索对「这个工作区看见哪些记忆」不再可能给出不同答案。
- **建表 DDL 下放到各表模块（`7be8bea`，@ZK-Andy）**：`data/schema.ts` 400 → 247 行，只留 guard 与聚合；`extraction_log`／`item_events`／`review_log`／`memories` 各自回本表模块，`migrate` 的 import 面不变。
- **配置读取归位（`7be8bea`，@ZK-Andy）**：`mountExtractionWhenAvailable` 改收已解析的布尔，`assemble.ts` 不再出现 `config.`；分层门禁 R3 扩到「非 `index.ts` 出现 `EvolveConfig` 即红」，并配规则级红绿样例。
- **规范与门禁对齐（`7be8bea`，@ZK-Andy）**：编码规范的 `try` 条款给事务／批处理开例外（判据是「`try` 内是一个完整事务」，不是语句条数）；预算棘轮 `--update` 必须带 `--reason <ADR>` 且指向存在的笔记，否则拒绝重定基线；评审档门禁把 `docs/plans`、`docs/research` 移出行为契约面。门禁矩阵 20 → 22 对。
- README 数据同步（`33a0a7c`，@ZK-Andy）：测试文件数、lint 命令与卡片归档区说明对齐当前形态。
- 修复计划与自审更正入 ADR（`b3ab32f`、`e44180f`，@ZK-Andy）。
- 已知余量与未覆盖面：投影收敛本批只覆盖 memories，技能读路径仍自带一份「本地遮蔽全局」实现；`data/review-accounts.ts` 因接收 `review_log` DDL 恰好 400/400、零余量。

<h3 id="en-v0.19.3">Removals</h3>

- **The eval task-set's retired surface is deleted outright (`7be8bea`, @ZK-Andy)**: `services/eval-taskset.ts` and its test are gone — after the synthetic four-arm loop was killed it had zero production references, only its own test referenced it, yet it still shipped in the package. `store.writeEvalCases` and the write surface of `data/eval-cases.ts` come down with it (table shape and the 30-day pruning stay), along with the zero-consumer constants that only served that write path (`EVAL_*_CHAR_CAP`, `EVAL_LAST_FOUR_ARM_KEY`, …) and `redactText`. The `files` allowlist drops `evals/tasks` and `evals/baseline` — kept in the repo, shipped to nobody. Rationale: ADR `2026-10-20-architecture-drift-remediation`.

<h3 id="en-v0.19.3-fixes">Bug Fixes</h3>

- **The card's archived zone now renders like the list (`7be8bea`, @ZK-Andy)**: archived rows go through the list-row renderer's read-only branch (badges and expansion kept, preview and actions off), and the five `archive_reason` values move into a card-level inline dictionary (zh/en) — a Chinese UI no longer shows a raw English enum. One memory used to have two shapes in the same card.
- **Promoted archived rows point at their live global copy (`7be8bea`, @ZK-Andy)**: `globalCopyId` is given only when `archive_reason = promoted-source` and the global live row's `origin_workspace` is exactly this workspace; the badge reads "content lives in global (id)" and keeps the id segment for manual reconciliation. Partitions are isolated, so another partition's same-id global row is not this memory's live copy — the pointer never misleads. A promoted row no longer reads as "the content was revoked".

<h3 id="en-v0.19.3-other">Other Changes</h3>

- **One projection rule (`7be8bea`, @ZK-Andy)**: "a local row shadows the global row with the same id" is defined once, in `data/memory-reads.ts`'s `globalOnly`; injection, search, and the card's `mergedVisible` each pass their own candidate set. The card and the injection/search path can no longer disagree about "which memories does this workspace see".
- **Table DDL moves down into its own table modules (`7be8bea`, @ZK-Andy)**: `data/schema.ts` goes 400 → 247 lines, keeping only guards and aggregation; `extraction_log` / `item_events` / `review_log` / `memories` go back to their modules, with `migrate`'s import surface unchanged.
- **Config reads move to the assembly root (`7be8bea`, @ZK-Andy)**: `mountExtractionWhenAvailable` now takes an already-resolved boolean and `assemble.ts` no longer mentions `config.`; the layering gate R3 widens to "an `EvolveConfig` outside `index.ts` is red", with rule-level red/green samples.
- **Standards and gates realigned (`7be8bea`, @ZK-Andy)**: the coding standard's `try` clause gets an exception for transactions and batches (the test is "one complete transaction inside `try`", not a statement count); the budget ratchet's `--update` now requires `--reason <ADR>` pointing at an existing note, otherwise the baseline reset is refused; the review-tier gate moves `docs/plans` and `docs/research` out of the behavior-contract surface. The gate matrix grows 20 → 22 pairs.
- README data sync (`33a0a7c`, @ZK-Andy): test-file count, lint command, and the card's archived-zone description match the current shape.
- Remediation plan and self-review corrections landed in the ADR (`b3ab32f`, `e44180f`, @ZK-Andy).
- Known headroom and uncovered ground: this batch's projection convergence covers memories only — the skill read path still carries its own "local shadows global" implementation; `data/review-accounts.ts` sits at exactly 400/400 lines after taking the `review_log` DDL, with zero headroom.
