<h3 id="cn-v0.16.4">v0.16.4 — 后台轨路由与失败纪律</h3>

后台两条轨（提取 / 评审）读的是 **agent 创建期的模型快照**：会话中途换模型后，两条轨仍按旧模型发请求，而失败既没有分级、也没有退避——被拒的路由在每个回合边界被重打一遍（2026-10-16 实测：一个已切到 flash 的会话留下 10 条 `AUTH` 403，每次两发）。本版把路由真值改成**会话当前选择**（按宿主自己的顺序），给两条轨补上失败纪律，并修掉老库账本表的形状漂移与设置卡开关的样式。

### 新功能

- 路由真值按宿主的顺序解析（@ZK-Andy）<!-- d27dbca -->：会话 `modelSelection` 投影的 `pending ?? lastUsed` → 会话上一份请求头 → agent 创建期 `options` → 主机默认；任一档不可达即退下一档，四档皆无仍拒绝发送。每次 drain 落一行 `route-resolved`（带命中档位）——"修复真生效"与"悄悄退回旧行为"不再同形。
- 失败纪律（@ZK-Andy）<!-- 4a7c448 -->：分类只读宿主的稳定 code（`AUTH` / `NO_ADAPTER` 等为终态，其余含未知一律瞬态）。被拒的路由在路由变化前不再调用；瞬态故障按 0 → 5 分钟 → 15 分钟 → 1 小时 → 6 小时退避，成功或换路由清零；被抑制的回合按合并行记账、游标不动（内容不丢）。评审轨遇终态即中止整批，其余候选留队、每次至多花 1 格预算。

### 问题修复

- 设置卡开关改吃宿主 Switch 原语（@ZK-Andy）<!-- 6c86be7 -->：宿主没有该原语时回退原生 checkbox，样式不再自成一派。
- 老库账本表的形状漂移（@ZK-Andy）<!-- 2426afd -->：`extraction_log` 的 `item-review` 白名单此前只落在新建的库上，老库撞 CHECK 抛错——而本体已 COMMIT，于是"本体已改、审计行丢失、台账记成失败"。现在按值集比对自动重建（事务内、显式列清单、回放索引），并把三条写入通道的审计行移进与本体同一个事务：写不进去就整批回滚。

### 其他改动

- 后台轨三修 ADR 补齐五处缺口后落地并转 implemented（@ZK-Andy）<!-- 15f9f8e --> <!-- 00cac87 -->
- 事件驱动评审取代到期全量重审（ADR，proposed）（@ZK-Andy）<!-- ec5649f -->
- 卡片与文档术语统一："回炉" → "重审"（@ZK-Andy）<!-- b1bd796 -->
- 双语 README 数据同步（548 测试、覆盖 97/92）
- 账本"最新一行"的测试改按插入顺序取（@ZK-Andy）<!-- d7f51dc -->：审计行与本体同事务后，两次批次之间不再隔一次 fsync，毫秒戳会并列——并列时按 ts 挑行是掷硬币。

<h3 id="en-v0.16.4">v0.16.4 — Background-track routing and failure discipline</h3>

Both background tracks (extraction and review) resolved their model from the **agent's creation-time snapshot**, so a session that switched models mid-conversation kept seeing its background calls sent to the model it had left — and failures had no grading, no counter, and no backoff, so a refused route was retried on every turn boundary (measured 2026-10-16: ten `AUTH` 403s in one session that had already moved to flash, two calls each). This release reads the **session's current selection** instead (in the host's own order), gives both tracks a failure discipline, and fixes both the ledger-shape drift on existing stores and the settings switches' styling.

### Features

- Route truth in the host's own order (@ZK-Andy) <!-- d27dbca -->: the session's `modelSelection` projection (`pending ?? lastUsed`), then its last request header, then the agent's creation-time `options`, then the host default — each candidate skipped when it cannot answer, and "no candidate" still refuses to send. Every drain logs one `route-resolved` line naming the candidate that answered, so a fix that silently degrades to the old behaviour no longer looks like a fix.
- Failure discipline (@ZK-Andy) <!-- 4a7c448 -->: classification reads the host's stable code only (`AUTH` / `NO_ADAPTER` and friends are terminal; everything else, including codes never seen, is transient). A refused route is not called again until the route changes; transient faults back off 0 → 5min → 15min → 1h → 6h and reset on success or a route change; suppressed wake-ups land one coalesced ledger row and leave the cursor alone (nothing is dropped). The review track stops a whole drain on a terminal failure, leaving the remaining candidates queued and spending at most one budget slot.

### Bug Fixes

- Settings switches ride the host's Switch primitive (@ZK-Andy) <!-- 6c86be7 -->: falling back to a native checkbox on hosts without it, instead of carrying their own look.
- Ledger-shape drift on existing stores (@ZK-Andy) <!-- 2426afd -->: `extraction_log`'s `item-review` whitelist only ever reached newly created stores, so an existing store threw on the audit insert — after the body had committed, leaving an edit with no audit row and a ledger line calling it a failure. The store now rebuilds a drifted table by comparing value sets (inside one transaction, with an explicit column list and replayed indexes), and all three write channels put their audit row in the same transaction as the body: if it cannot be written, nothing is.

### Chores

- The three-fix ADR grew five gaps, then landed and moved to implemented (@ZK-Andy) <!-- 15f9f8e --> <!-- 00cac87 -->
- Event-driven review replacing the stale requeue (ADR, proposed) (@ZK-Andy) <!-- ec5649f -->
- One term across card and docs: "回炉" → "重审" (@ZK-Andy) <!-- b1bd796 -->
- Bilingual README data sync (548 tests, 97/92 coverage)
- The ledger "latest row" test now picks by insertion order (@ZK-Andy) <!-- d7f51dc -->: with the audit row committing alongside its body, no fsync separates two batches any more, so their millisecond stamps tie — and picking a row by `ts` on a tie is a coin flip.
