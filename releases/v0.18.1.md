<h3 id="cn-v0.18.1">问题修复</h3>

- **试运行不再在账本里声称「转正」。** 实习期满的全局条目若拿到 keep 判词，`review_log` 原来一律写「实习转正（有跨分区引用）」——试运行（`review.dryRun`）下什么都没改却写着转正，读账本的人会被误导。现在分三种措辞：无跨分区引用（试运行）、有引用但仅试运行（「本会转正」）、真转正。这是 v0.18.0 的账本措辞修正，不影响任何状态变化。(@ZK-Andy) <!-- c06b4b5 -->
- **CI 覆盖率门禁修复。** v0.18.0 的 CI 在按文件覆盖率门禁（91/83）上失败：新增的 `data/tiering.ts`、`services/review-tiering.ts`、`services/review-row.ts` 首版只到 83/44/78。补 38 例覆盖「拒绝理由、事务回滚重抛、证据表不可读不授权、试用三出口、技能拒绝层级判词、候选标记清除失败」等分支；顺带把 `evolved` 从可选链改成显式入参（去掉一批不可达分支）、删除未使用的 `verdictCount` 助手。现全仓 640 测试、覆盖率 97.75 / 93.13。(@ZK-Andy) <!-- c06b4b5 -->

<h3 id="en-v0.18.1">Bug Fixes</h3>

- **Trial mode no longer claims a confirmation it never made.** A keep verdict on a global row whose probation came due used to ledger「实习转正（有跨分区引用）」unconditionally — under `review.dryRun` nothing changed while the row said it had been confirmed. The wording now has three cases: no cross-partition use (trial), use but trial only ("would have been confirmed"), and a real confirmation. Wording fix only; no state change differs. (@ZK-Andy) <!-- c06b4b5 -->
- **CI coverage gate fixed.** v0.18.0's CI failed the per-file coverage floor (91/83): the new `data/tiering.ts`, `services/review-tiering.ts`, and `services/review-row.ts` started at 83/44/78. 38 cases now cover the refusal reasons, transaction rollback-and-rethrow, an unreadable evidence table not authorizing a move, the three probation exits, skills refusing tiering verdicts, and a failed candidacy clear; `evolved` moved from optional chaining to an explicit parameter (dropping a batch of unreachable branches) and the unused `verdictCount` helper is gone. 640 tests, coverage 97.75 / 93.13. (@ZK-Andy) <!-- c06b4b5 -->
