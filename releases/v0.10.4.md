<h3 id="cn-v0.10.4">问题修复（快照门禁 settings 解析）</h3>
- 每成功回合快照门禁通过直接属性访问读取宿主 settings 服务，Cordis 只沿调用方 fiber 祖先链解析直接属性访问，对兄弟插件条目提供的服务抛 `cannot get property "settings" without inject`，导致每次快照在 LLM 调用前整批中止（memory 抽取静默停摆）；改走 `ctx.get("settings")` 全局服务注册表（与 `goal.ts` 同款模式）并对访问加守卫，使文档声明的 fail-open 契约在 Cordis 上下文下真正成立；纯对象宿主经直接属性回退继续工作 (6673fb3) (@zhangkun)

<h3 id="en-v0.10.4">Bug Fixes (snapshot-gate settings resolution)</h3>
- The per-success-turn snapshot gate read the host settings service through a direct `ctx.settings` property access. Cordis resolves direct property reads only along the caller's fiber ancestor chain and throws `cannot get property "settings" without inject` for services provided by sibling plugin entries, aborting every snapshot before the LLM call (memory extraction silently dead). Resolve through `ctx.get("settings")` (the global service registry, same pattern as `goal.ts`) and guard the access so the documented fail-open contract actually holds on Cordis contexts; plain-object hosts keep working via the direct-property fallback (6673fb3) (@zhangkun)
