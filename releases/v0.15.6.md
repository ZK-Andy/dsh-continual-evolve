<h3 id="cn-v0.15.6">v0.15.6 — 技能使用回路 + 质量评审取回：闭环的反馈边</h3>

S1 只管存与看，不管用与审。这一版补上自进化闭环的反馈边：技能被取用留下计数，提取的每次判断与花费留下审计——沉淀下来的东西第一次有了"有没有人用、判得怎么样"的证据。

### 新功能

- **技能使用回路 V2**（@ZK-Andy，`2f8e3df`）：`skill_read` 按 id 取回正文、卡片技能预览命中时各计一次取用（只记正文取回，检索/列表是噪声不记）。聚合表 `skill_usage`（主键三元组，无无界增长、无需裁决）；记账永不打断读。卡片技能行透出 `useCount`/`lastUsedAt`（双语"用过 N 次"）；剪枝规则第一次有证据可用。实现中发现宿主自带技能发现 + 懒加载（本会话 catalog 秒级更新实证），插件侧索引注入是重复功能——V2 改做使用回路，原方案在 ADR 留档。
- **质量评审取回**（@ZK-Andy，`391dd01`）：`docs/coding-standard.md` 点名的 `token-usage.ts` 回来了——`normalizeUsage` 把真库 20 余种实测用量形状归一，`sumUsage` 纯累加，以后任何 LLM 调用点记账只走它。`store.reviewSummary` 只读聚合判断计数、top 3 skip 原因与 token 总量，失败降级零值。评审行搭记忆快照进卡片（无新路由、无新增请求，有判断才显示）。10-04 的结论仍然有效：不恢复审批/回滚，只取回记账与审计。
- 测试 258 → 273 例（新增 15 个使用回路与评审回归），typecheck/lint/文档门禁/`check:pack` 全绿；覆盖率水位守住（`token-usage.ts` 100%）。

### 升级提示

- 无配置变更、无破坏性变更、无库迁移（新表 `CREATE IF NOT EXISTS`，旧库打开即建）。
- dotnet-desktop 是 npm 实体拷贝：更新到 0.15.6 并重启 profile 后，**请硬刷新 GUI 页面**（Ctrl+Shift+R）。
- 验收：卡片技能行出现"用过 N 次"（`skill_read` 取一次正文即 +1）；记忆区统计行下出现评审行（应用/拒绝/跳过/失败计数 + token 总量）。

<h3 id="en-v0.15.6">v0.15.6 — skill usage loop + review-loop retrieval: the feedback edge</h3>

S1 covered storing and viewing, but not using and auditing. This release closes the feedback edge of the self-evolution loop: skill consumptions leave counts, and every extraction judgment and its cost leaves an audit — sedimented knowledge finally carries evidence of "is anyone using it, how are judgments going".

### Features

- **Skill usage loop V2** (@ZK-Andy, `2f8e3df`): one counted use per skill body served by id via `skill_read` and per card skill preview hit (bodies only — search/list hits are noise and stay uncounted). Aggregate table `skill_usage` (triple primary key, bounded, no pruning needed); accounting never fails the read it rides on. Card skill rows expose `useCount`/`lastUsedAt` (bilingual "used N times"); the pruning rule has evidence for the first time. During implementation we found the host already ships skill discovery plus lazy loading (this session's catalog updated within seconds), so a plugin-side index injection would duplicate it — V2 became the usage loop instead, with the original plan kept on record in the ADR.
- **Review-loop retrieval** (@ZK-Andy, `391dd01`): the `token-usage.ts` named by `docs/coding-standard.md` is back — `normalizeUsage` unifies 20+ observed payload shapes, `sumUsage` aggregates purely, and every future LLM call site accounts through it. `store.reviewSummary` read-only aggregates judgment counts, top-3 skip reasons, and token totals, degrading to zeros on faults. The review line rides the memory snapshot into the card (no new route, no extra request, shown only when judgments exist). The 10-04 conclusion stands: no approval/rollback restoration, only accounting and audit.
- Tests 258 → 273 (15 new usage-loop and review regressions); typecheck, lint, docs gates, and `check:pack` all green; coverage floors held (`token-usage.ts` at 100%).

### Upgrade notes

- No config changes, no breaking changes, no store migration (new tables are `CREATE IF NOT EXISTS`, built on open).
- dotnet-desktop resolves the plugin as an npm copy: after updating to 0.15.6 and restarting the profile, **hard-refresh the GUI page** (Ctrl+Shift+R).
- Acceptance: card skill rows show "used N times" (one `skill_read` body fetch adds one); a review line appears under the memory stats (applied/rejected/skipped/failed counts plus token totals).
