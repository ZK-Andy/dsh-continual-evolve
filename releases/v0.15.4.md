<h3 id="cn-v0.15.4">v0.15.4 — 提取轨意外异常也有账本行</h3>

上一版让失败可回查（解析失败留原文）、让噪声收敛（空转合并计数）；本版补上最后一块真空地带：管线内任何未预期的抛错——`store.list/search`、prompt 组装、`applyProposals` 抛错、游标/巡检写入、账本写入本身——原先只剩调度器里一句 `host.logger.warn`，而 host 日志连启动行都没有落点，等于真静默。

### 问题修复

- **意外异常账本留痕**（@ZK-Andy，`1b690c2`）：`runExtraction` 包一层 catch-all，任何逃逸异常都落 `failed` 账本行——`skip_reason` 为 `unexpected-error: <message 头>`，`files` 带 message+stack 头 2KB，model 与耗时俱全；游标不动，下轮触发重试。failed 行逐行保留，不参与空转合并；`patrol` 抛错时 applied 行与失败行并存，失败行不吞没已落地事实。只有账本本身也写不进时才 rethrow，且把触发错误与账本错误串成一条链。
- **旧失败行补错误原文**（同上）：`surface-read-failed` / `llm-failed` 原先只有短因、无诊断，现在 `files` 带错误原文，`skip_reason` 保持稳定。
- **调度器 warn 前重试账本**（同上）：`drain().catch` 在 warn 前再试一次账本写入——瞬时账本故障即重试，排水前序抛错即唯一留痕；写不进则只 warn，回调本身永不抛错。
- 测试 194 → 199 例（`test/extraction.test.ts` 24 → 29），typecheck/lint/文档门禁全绿。

### 升级提示

- 无配置变更、无破坏性变更、无库迁移（复用既有列，无需 `ALTER TABLE`）。
- dotnet-desktop 是 npm 实体拷贝：更新到 0.15.4 并重启 profile 后，**请硬刷新 GUI 页面**（Ctrl+Shift+R）。
- 验收：实体拷贝 `package.json` 版本为 0.15.4；账本若出现 `unexpected-error` 行，其 `skip_reason` 带 message 头、`files` 可 JSON 解析出 message+堆栈。

<h3 id="en-v0.15.4">v0.15.4 — unexpected extraction failures get a ledger row</h3>

The previous release made failures diagnosable (raw answer on parse failure) and folded the noise (quiet-turn coalescing); this one closes the last blind spot: any unexpected throw inside the pipeline — `store.list/search`, prompt assembly, an `applyProposals` throw, cursor/patrol writes, even the ledger write itself — previously ended as a single `host.logger.warn` in the scheduler, while the host log has no sink for even its startup line. Truly silent.

### Bug Fixes

- **Unexpected errors leave a ledger row** (@ZK-Andy, `1b690c2`): `runExtraction` gains a catch-all — any escaped error lands a `failed` ledger row with `skip_reason` `unexpected-error: <message head>` and `files` carrying the message+stack head (2KB), model and duration included; the cursor stays put for a retry on the next trigger. Failed rows stay one row per occurrence (no coalescing); when `patrol` throws, the applied row and the failure row coexist — the failure never hides landed facts. Only if the ledger itself is unwritable does it rethrow, chaining the triggering error with the ledger error.
- **Older failure rows gain the error text** (same): `surface-read-failed` / `llm-failed` used to carry only a short reason with no diagnosis; their `files` now hold the error text while `skip_reason` stays stable.
- **The scheduler retries the ledger before warning** (same): `drain().catch` attempts one ledger write before the warn — a retry for transient ledger faults, the only trace for a pre-drain throw; if that fails it only warns, and the callback never throws.
- Tests 194 → 199 (`test/extraction.test.ts` 24 → 29); typecheck, lint, and docs gates all green.

### Upgrade notes

- No config changes, no breaking changes, no store migration (existing columns reused, no `ALTER TABLE`).
- dotnet-desktop ships an npm copy: after updating to 0.15.4 and restarting the profile, **hard-refresh the GUI page** (Ctrl+Shift+R).
- Acceptance: the npm copy's `package.json` reads 0.15.4; if an `unexpected-error` row appears in the ledger, its `skip_reason` carries the message head and its `files` JSON-parse to message+stack.
