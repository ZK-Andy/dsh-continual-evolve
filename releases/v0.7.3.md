<h3 id="cn-v0.7.3">新功能</h3>

- 专用后台 Memory Extraction Agent：成功回合后的 eligible 增量 snapshot 由最多 5 个内部 turn 的专用 loop 提炼 memory；使用冻结 manifest、只读 `memory_search` 与结构化 `memory_propose`，不能调用 Agent、MCP、网络或源码工具。 @ZK-Andy <!-- b8c1b45 -->
- Memory agent 接入 `EvolutionEngine.apply()`：memory-only proposal、update-first、作用域审批、结构化 diff/冲突提示、project/global 全字段 secret 筛查与跨 scope 补偿回滚；失败/abort 不推进 memory phase checkpoint，通用 planner 的 memory 分支被机械剥离。 @ZK-Andy <!-- b8c1b45 -->
- Token 账本新增独立 `memory` phase；snapshot capture 按 session 串行，scheduler 按最高已结算 boundary 合并，迟到 snapshot 不会回退 cursor。 @ZK-Andy <!-- b8c1b45 -->

<h3 id="en-v0.7.3">Features</h3>

- Added a dedicated background Memory Extraction Agent. Eligible incremental snapshots after successful turns now feed a bounded five-turn loop with a frozen memory manifest, read-only `memory_search`, and structured `memory_propose`; Agent, MCP, network, and source-writing tools are unavailable. @ZK-Andy <!-- b8c1b45 -->
- Connected the memory agent to `EvolutionEngine.apply()` with memory-only proposals, update-first behavior, scoped human approval, structured diffs and conflict warnings, persistent-scope secret screening, and compensating rollback across scopes. Memory failures and aborts do not advance the memory checkpoint, and memory edits returned by the general planner are mechanically removed. @ZK-Andy <!-- b8c1b45 -->
- Added a dedicated `memory` phase to the direct-call token ledger. Snapshot capture is serialized per session, and pending scheduler work is coalesced by the highest settled boundary so late snapshots cannot move cursors backward. @ZK-Andy <!-- b8c1b45 -->

### Bug Fixes

- Direct LLM calls now select the lowest reasoning effort advertised by the exact provider/model instead of assuming `off` is valid. @ZK-Andy <!-- cecd150 -->
- Capability resolution prefers the model's lowest enabled effort, falls back to a closing effort only when no enabled level is advertised, and omits the field when no reasoning metadata is exposed. @ZK-Andy <!-- 69df385 -->

### Chores

- Added regression coverage for the memory agent, approvals, compensation, cursors, out-of-order scheduling, multi-session isolation, disposal, and token accounting; updated the baseline to 737 tests / 44 files.
- Synchronized the bilingual README, design document, FAQ, ZCode research notes, and HANDOFF. Coverage: 92.53% statements / 82.90% branches / 95.85% functions.
