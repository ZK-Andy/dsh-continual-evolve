<h3 id="cn-v0.18.0">新功能</h3>

- **记忆分层：L0 跟人走、L1 跟项目走。** 记忆现在分两层——L0（协作偏好、语言、工作方式、本机环境事实）住全局分区，L1（项目现状、机制指针、命令、门禁）住各工作区分区，L2（会话/任务状态）依旧不进库。读路径把全局分区合并进每个工作区的视图，**L0 排在 L1 之前**（注入索引因此先看到人物画像），同 id 时活动的本地行遮蔽全局行；归档行不遮蔽——提级后的源行正是归档状态。卡片的分区视图不合并，免得每行出现两次。(@ZK-Andy) <!-- 821dd57 -->
- **两级试用漏斗，取代「一次判定就落全局」。** 提取时归属三测全过会在提案里打 `scope=person`（条目仍住原分区，只作候选标记，非法值就地丢弃不让整批被拒）；评审的第二次独立判定说 promote 才真的移动。移动是单事务：全局建行 + 项目行归档（永远只有一份 active）+ 目标分区补一条判词行，所以搬过去的行读作「已判」而不是「新写」。进全局带 30 天实习期并记住来源分区，实习行照常注入、标「（试用中）」——看不见的记忆赚不到跨项目引用。到期由队列的**时钟档**送去复审（不受最长免审期与抽样配额压制）：非来源分区有过引用就转正，没有就退回来源分区，真过时/涉密则隔离。(@ZK-Andy) <!-- 821dd57 -->
- **「放错家」有了四个出口，不再一律隔离。** 评审新增三种判词：`archive`（内容没错但压根不该长期存在——保留历史、不再注入、按 id 仍可查；门槛是零引用 + 第二次独立淘汰判定 + 没有被任何活动条目 `corrects` 指向）、`promote`（人物画像该进 L0）、`demote`（绑某仓库的条目却住在全局，退回项目分区）。另有 `export-suggestion`：「内容对，但家该是仓库文档」——只记判词并在卡片标「建议入仓文档」，**绝不自动往你的仓库写文件**（那会绕过 ADR 流程与文档门禁）。物理删除仍然只由人做。(@ZK-Andy) <!-- 821dd57 -->
- **手动兜底与账本**：`evolve_write(kind=memory, action="move-to-global")` 把一条记忆手动提到全局（默认也进实习）；`review_log` 的 verdict 白名单随之扩展，老库打开时由 schema guard 重建一次，历史判词一条不丢。(@ZK-Andy) <!-- 821dd57 -->

<h3 id="en-v0.18.0">Features</h3>

- **Memory layers: L0 follows the person, L1 follows the project.** Memories now live on two levels — L0 (collaboration preferences, language, working style, machine facts) sits in the global partition, L1 (project state, mechanism pointers, commands, gates) in each workspace partition, and L2 (session/task state) still never enters the store. Reads merge the global partition into every workspace view with **L0 first** (so the injection index leads with the person-level facts), and an active local row still shadows a global one by id — an *archived* row shadows nothing, which is exactly the state a promotion leaves behind. The card's per-partition view stays unmerged so no row is listed twice. (@ZK-Andy) <!-- 821dd57 -->
- **A two-stage promotion funnel replaces "judge once, write globally".** When all three ownership tests pass, extraction marks the proposal `scope=person` (the row stays in its project — the marker is only a candidacy, and an invented value is dropped on the spot instead of rejecting the whole batch); the review's second, independent judgement has to say promote before anything moves. The move is one transaction: build the global row, archive the project row (exactly one active copy ever), and leave a verdict row in the target partition so the moved row reads as judged rather than brand new. A promoted row starts a 30-day probation and remembers its origin partition; probation rows are injected like any other and tagged「试用中」— an unseen memory cannot earn the cross-partition use that confirms it. When the window closes, the queue's **clock tier** brings it back (outranking both the exemption window and the sampling quota): a reference from a partition other than the origin promotes it for good, none sends it home, and a genuinely stale or leaked row is quarantined. (@ZK-Andy) <!-- 821dd57 -->
- **"Wrong home" now has four exits instead of quarantine for everything.** The review gained three verdicts: `archive` (nothing wrong with the content, it simply should not exist long-term — history kept, no longer injected, still readable by id; gated on zero references, a second independent reject verdict, and no active row pointing at it via `corrects`), `promote` (person-level facts belong in L0), and `demote` (a repo-bound row that somehow sits in the global partition goes back to its project). A fourth, `export-suggestion`, means "the content is right but its home is the repo's docs": it records the advice and tags the row「建议入仓文档」on the card, and **never writes into your repository** (that would bypass the ADR flow and the doc gates). Physical deletion remains human-only. (@ZK-Andy) <!-- 821dd57 -->
- **Manual fallback and ledger**: `evolve_write(kind=memory, action="move-to-global")` promotes a memory by hand (it enters probation too); the `review_log` verdict whitelist grows with these exits, and the schema guard rebuilds an older store once on open without losing a single historical verdict. (@ZK-Andy) <!-- 821dd57 -->
