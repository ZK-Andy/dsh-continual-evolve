<h3 id="cn-v0.16.5">新功能</h3>

- **落点测试：事实落进仓库文件后不再重复提取。** 提取提示词在归属三测之外新增一条判据——用户已把某条规则写进、或明确要把它写进仓库里的任何文件时，那个文件就是它的家，提取判 skip 并在理由里引用原话；同一句话在记忆与仓库文件各存一份即视为违规。判据挂在「事实落进仓库」这个动作上，不枚举任何文件名、目录或后缀，因此新增或改名工作区规则文件都不需要插件发版。便宜预检门同步加上同一判据。(@ZK-Andy) <!-- bd079ea -->
- **提取增量带上本轮工具名。** 序列化增量时在头部加一行 `tools-this-turn`，只取工具名，参数与路径永不进入提示词——模型由此知道「本轮发生过文件写入」，但仍需自己判断哪条事实落进了哪个落点。该行占用的字符从正文预算中扣减，超长或超量的工具名有截断与去重上限。(@ZK-Andy) <!-- bd079ea -->

<h3 id="en-v0.16.5">Features</h3>

- **Landing-point test: a fact that already lives in a repo file is no longer extracted into memory.** The extraction prompt gains a fourth ownership check: when the user has written a rule into — or explicitly asked to write it into — any file in the workspace, that file is the fact's home; the run skips with the user's own words quoted in the reason. One sentence living in both a memory and a repo file now counts as a violation. The rule keys on the *act* of landing in the repo and names no file, directory, or suffix, so adding or renaming a workspace rule file never requires a plugin release. The cheap pre-gate applies the same check. (@ZK-Andy) <!-- bd079ea -->
- **The extraction increment now names the turn's tools.** Serialization prepends a `tools-this-turn` line carrying tool names only — arguments and paths never enter the prompt — so the model can tell that a file write happened, while still judging which fact landed where. Its length comes out of the body budget, and oversized or excessive tool names are truncated and de-duplicated. (@ZK-Andy) <!-- bd079ea -->
