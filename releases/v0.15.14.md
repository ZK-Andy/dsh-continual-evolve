<h3 id="cn-v0.15.14">v0.15.14 — 一次账目对不上：失败留痕与账目完整性</h3>

一次体检引出的修复。真库 `review_daily` 里出现当日行只有 `reviewed = 9`、`new_items` / `requeued` / `approved` / token 全为 0，而同日 9 条 `review_log` 行都是正常的 `keep` verdict——批次跑过，账目只落了一半。往下查是两处结构问题：写入分成「逐条扣额度」与「收尾一次合并」两条互不覆盖的路径，异常落在中间就留下半截账；而这条路径的失败**设计上无痕**——收尾合并是账目动作、不写 `review_log`，调度器 `catch` 只 `warn`，而插件 `ctx.logger` 输出在本机不落任何可查文件。本版把「失败记成值」这条纪律补到评审轨：单条异常不再吞掉整批，账目必达，失败落进库台账。

### 问题修复

- **单条异常不再吞掉整批**（@ZK-Andy，`b12b7bc`）：链上任何异常（store 写失败、wiring bug）降级为一条 `review-failed: <错误原文首行>` 的 skip 行并计入当日跳过桶，批次继续走下一条。此前它会直接冲出 `runReviewBatch`，同一批次余下条目连同整批账目一起丢——链上原有的降级只覆盖模型侧失败（门/贵门 LLM 与解析）。
- **账目必达**（@ZK-Andy，`b12b7bc`）：`mergeDaily` 移进 `finally`，无论循环正常结束、额度用尽 `break` 还是抛异常，当日计数都会合并；异常在合并**之后**重抛，fail loud 不变。异常批次因此也留得下完整账目。
- **drain 级留痕**（@ZK-Andy，`b12b7bc`）：成功记 `review drain: reviewed N, approved M, …`；失败先 `warn` 错误原文，再把 `drain-failed: <错误原文>` 写进当日 `review_daily.skip_counts`（持久、可回读），若连这次记录也失败再 warn 一次；额度用尽跳过也记 info。

### 升级提示

- 无破坏性变更，无 schema 变更（旧库直接可用）。
- dotnet-desktop 是 npm 实体拷贝：更新到 0.15.14 后**重启 App** 即生效（`client/` 本版未动，无需硬刷）。
- 评审环保持试运行（`review.dryRun` 默认开）：本版不改开关，只补失败可见性与账目完整性。
- **已知边界（本版查实）**：插件的 `ctx.logger` 输出在本机不落 `~/.dsh/logs/host.log`（该文件只有 shell / host / update / supervisor / tray / nav / bootstrap / health / cli-shim / caption-bar 这些 scope，插件 scope 0 行）。因此凡是需要事后复盘的事实一律写库台账（`review_log` / `review_daily`），logger 只作实时通道。
- 测试 395 → 397（新增 2 例：单条故障后账目完整且留痕、drain 失败落进当日 rollup）；typecheck / lint / 文档门禁 / `check:pack` 全绿。
- **归因更正**：发布后复核了那条「半截」日行——当日总账 `reviewed=18 = new_items 2 + requeued 16` 自洽，说明没有合并丢失；那是在**批次进行中**读到的快照（`reviewed` 逐条原子递增以守额度，其余计数收尾合并）。本版修的是代码里确实存在的缺口：异常冲出循环会连整批账目与原因一起丢。

<h3 id="en-v0.15.14">v0.15.14 — an account that did not add up: failure traces and whole ledgers</h3>

This release came out of one audit. A production `review_daily` row for the day held `reviewed = 9` while `new_items`, `requeued`, `approved` and both token counters sat at zero — yet the same day's nine `review_log` rows were all ordinary `keep` verdicts. The batch had run; only half of its account landed. Underneath were two structural gaps: the writes split into "consume one unit of budget per item" and "merge every counter once at the end", so an exception in between left a half-written row; and that path failed **by design without a trace** — the closing merge is an accounting step that writes no `review_log` row, the scheduler's `catch` only warned, and the plugin's `ctx.logger` output reaches no readable file on this host. This release applies the "failures are values" discipline to the review track: one item's fault no longer kills the batch, the day's account always lands, and failures leave a durable ledger trace.

### Bug Fixes

- **One item's fault no longer kills the batch** (@ZK-Andy, `b12b7bc`): any exception escaping the chain (a store write, a wiring bug) now degrades to a `review-failed: <error head>` skip row counted into the day's skip buckets, and the batch moves on to the next item. Before, it escaped `runReviewBatch` outright, taking the rest of the batch and the whole run's account with it — the ring's existing degradation covered only model-facing failures (gate/evolve LLM and parsing).
- **The day's account always lands** (@ZK-Andy, `b12b7bc`): `mergeDaily` moved into a `finally`, so the counters merge whether the loop finishes, breaks on an exhausted budget, or throws; the error is rethrown *after* the merge, so failing loud is unchanged. A failed run therefore still leaves a complete account for the day.
- **Drain-level traces** (@ZK-Andy, `b12b7bc`): a successful drain logs `review drain: reviewed N, approved M, …`; a failed one warns the error text and then writes `drain-failed: <error head>` into that day's `review_daily.skip_counts` (durable and readable back), warning once more if even that write fails; a drain skipped for an exhausted budget logs too.

### Upgrade notes

- No breaking changes, no schema change (existing databases work as they are).
- dotnet-desktop is an npm copy: update to 0.15.14 and **restart the app** (`client/` is untouched, no hard refresh needed).
- The review ring stays in trial mode (`review.dryRun` defaults on): this release changes no switch, only failure visibility and ledger completeness.
- **Known boundary (established in this release)**: the plugin's `ctx.logger` output reaches no readable file on this host (`~/.dsh/logs/host.log` carries only the shell / host / update / supervisor / tray / nav / bootstrap / health / cli-shim / caption-bar scopes — zero plugin scopes). Facts that must survive for a later post-mortem therefore go into the store's ledgers (`review_log` / `review_daily`); the logger is the live channel only.
- Tests 395 → 397 (two new: an item fault keeps the account whole and leaves a trace, a failed drain lands in the day's rollup); typecheck, lint, docs gates and `check:pack` all green.
- **Attribution corrected**: after publishing we re-checked that "half-written" row — the day's totals balance (`reviewed = 18 = new_items 2 + requeued 16`), so no merge was ever lost; the row was read **while a batch was in flight** (`reviewed` increments atomically per item to enforce the cap, the other counters merge at the end). What this release fixes is the gap that does exist in the code: an exception escaping the loop takes the whole run's account and its reason with it.
