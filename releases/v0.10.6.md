<h3 id="cn-v0.10.6">问题修复（审批弹窗语言 + 打字回复）</h3>

- **审批弹窗不再回落到英文**——写 global/project 时的确认弹窗原来只读持久 locale 偏好（`<profile.home>/settings.yaml` 里的 `locale.preference`），而这个文件在桌面端常常不存在；配置项 `recordLanguage` 又因为四个调用点都没往下传而完全不起作用，于是中文用户拿到英文弹窗。现在审批弹窗走**与记录语言同一条链**：显式 `recordLanguage` → 持久客户端偏好 → **会话自身的用户文本** → `en`；`recordLanguage` 也逐层穿透到 tool / `/evolve plan` / wrapup / memory-agent 四条路径 (@zhangkun) <!-- f7655fd -->
- **在输入框里打字回复"批准"不再被判空**——上游把自由文本放在 `custom` 字段、`selected` 留空，旧解析只认 `selected` 的标签，于是抛 `invalid decision: []` 且什么都不写入。现在 `selected` 为空时会读取打字回复，**精确等于标签**即作数（`批准`/`approve`/`拒绝`/`decline`，容忍首尾空白、引号、尾随标点与"吧/了"）；其余情况抛可操作错误，明确提示要点选项按钮 (@zhangkun) <!-- f7655fd -->
- **同一缺陷家族的 wrapup 归档确认弹窗**一并纳入同一条语言链 (@zhangkun) <!-- f7655fd -->

> 打字只在**精确等于标签**时算决策：像"不批准"这种否定式**故意**不放行——误读一次决策比让用户点一下按钮严重得多。想让弹窗立刻变中文，正规路径是 **设置 → 通用 → 语言** 选一次（写入持久设置文档）；修链之后即使不设置，中文会话也会得到中文弹窗。

<h3 id="en-v0.10.6">Bug Fixes (approval dialog language + typed replies)</h3>

- **Approval dialogs no longer fall back to English** — the confirmation dialog for global/project writes only read the durable locale preference (`locale.preference` in `<profile.home>/settings.yaml`), a file that often does not exist on the desktop; and the `recordLanguage` config had no effect at all because none of the four call sites passed it down. Chinese-speaking users got English dialogs. Approval dialogs now run the **same chain as record language**: explicit `recordLanguage` → durable client preference → **the session's own user text** → `en`; `recordLanguage` is threaded through tool / `/evolve plan` / wrapup / memory-agent (@zhangkun) <!-- f7655fd -->
- **Typing "批准" in the input box is no longer read as an empty decision** — upstream carries free text in `custom` with `selected` left empty, and the old parser only accepted `selected` labels, so it threw `invalid decision: []` and wrote nothing. An empty `selected` now falls back to the typed reply, accepted when it **exactly matches a label** (`批准`/`approve`/`拒绝`/`decline`, tolerating surrounding whitespace, quotes, trailing punctuation, and a trailing 吧/了); anything else raises an actionable error naming the buttons to click (@zhangkun) <!-- f7655fd -->
- **The wrapup archive confirmation**, same defect family, now follows the same language chain (@zhangkun) <!-- f7655fd -->

> A typed reply counts only on an exact label match: negations like "不批准" are **deliberately** rejected — misreading one decision is far worse than asking the human to click a button. To make dialogs Chinese immediately, the supported path is **Settings → General → Language** (which writes the durable settings document); after this fix a Chinese session gets Chinese dialogs even without it.
