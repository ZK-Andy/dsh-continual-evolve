<h3 id="cn-v0.16.0">v0.16.0 — 分层落定，工具收敛</h3>

本版把经典分层＋通用仓储重构（P0–P7，之前已推送、随本版首次发版）与随后两轮"干净整洁"收敛一次发出来。核心两件事。**第一件**：模型可见工具收敛为**一个读、一个写**——`evolve_write(kind, …)` / `evolve_read(kind, …)`，`kind` 取 `memory`、`skill`、`prompt`；旧四个工具（`memory_write`/`memory_read`/`skill_write`/`skill_read`）按退役规则删除，不再跨版本共存。**第二件**：`src/store.ts` 从 1635 行单文件拆到 300 行装配（表现层 / 应用服务层 / 数据访问层 + 通用仓储），行为逐项等价——落盘结果与 id、门禁拒绝文案、账本行、投影文件字节、注入索引字节、卡片响应形状，测试 409 → 466 全绿。

### 新功能

- **统一读写工具**（@ZK-Andy，`833a189`+`c462810`）：`evolve_write(kind, action, scope, …)` / `evolve_read(kind, …)`，门禁组合按 `kind` 取，`scope: project | global` 覆盖搬家语义；旧四工具保留一版做薄垫片后按退役规则删除（`c462810`）。
- **第三类对象试接入：提示词补充**（@ZK-Andy，`3b08d51`）：`prompts`/`prompts_fts`/`prompt_log`/`prompt_usage` 四表 + `PROMPTS` 描述符，工具/卡片/投影/账本自动出现；`evolve_*` 的 `kind` 三元，评审环与注入刻意未做。
- **自带技能进仓库**（@ZK-Andy，`31ee2d5`）：手写 `evolve-skill-creator`（技能怎么写）+ `evolve-memory-creator`（记忆怎么写）进 `.agents/skills/`，`.agents/AGENTS.md` 技能节同步修订（`dsh-*` 上游原样 / `evolve_*` 自创）。
- **`change-scope` npm 入口**（@ZK-Andy，`ca67c63`）：三个 `dsh-*` 技能文案一直在调 `pnpm run change-scope`，但 `package.json` 里根本没有这个入口——转 TS 时顺手补上，它第一次真正可跑。

<h3 id="en-v0.16.0">v0.16.0 — layers settled, tools converged</h3>

This release ships the layered + generic-repository refactor (P0–P7, pushed before, first published here) together with two cleanup passes. Two things matter. **First**: the model-facing surface converges to **one read and one write** — `evolve_write(kind, …)` / `evolve_read(kind, …)` with `kind` of `memory`, `skill`, or `prompt`; the four legacy tools (`memory_write`/`memory_read`/`skill_write`/`skill_read`) are removed per the retirement rule, no cross-version coexistence. **Second**: `src/store.ts` goes from a 1635-line single file to a ~300-line assembly (presentation / service / data layers plus a generic repository), behavior held item-by-item — landed results and ids, gate rejection copy, ledger rows, projection bytes, injection bytes, card shapes — with tests going 409 → 466, all green.

### Features

- **Unified read/write tools** (@ZK-Andy, `833a189`+`c462810`): `evolve_write(kind, action, scope, …)` / `evolve_read(kind, …)`, gate bundles selected by `kind`, `scope: project | global` covering the move semantics; the four legacy tools survived one version as thin shims, then retired (`c462810`).
- **Third object kind: prompt supplements** (@ZK-Andy, `3b08d51`): four new tables plus the `PROMPTS` descriptor, with tools/card/projection/ledger appearing automatically; `evolve_*` takes a ternary `kind`. Review ring and injection deliberately out of scope.
- **Self-owned skills in the repo** (@ZK-Andy, `31ee2d5`): hand-written `evolve-skill-creator` (how to write skills) + `evolve-memory-creator` (how to write memories) under `.agents/skills/`, with the skills section of `.agents/AGENTS.md` revised (`dsh-*` upstream verbatim / `evolve_*` self-created).
- **The missing `change-scope` npm entry** (@ZK-Andy, `ca67c63`): three `dsh-*` skill docs invoke `pnpm run change-scope`, but `package.json` never had that entry — added during the TS port, so it runs for the first time.

### Bug Fixes

- **Lost `section-registered` log** (@ZK-Andy, `c462810`): moved into the store-ready `.then` (mount-complete semantics), pinned by a regression test on the `plugin_log` row.
- **Projection marker naming a retired tool** (@ZK-Andy, `fac1d4f`): the materialized marker still read `edit via skill_write` — now `evolve_write`; managed-file guards key on the stable signature fragment via `isManagedSkillFile`, so retired-marker files converge in one patrol (otherwise orphan files from the old wording would linger forever), pinned by regression tests.
- **Ledger SQL sunk into the data layer** (@ZK-Andy, `fac1d4f`): `services/memory-apply.ts` carried its own `LEDGER_SQL`, verbatim-duplicated from `prepareLedgerStmts().ledger` — the constant is gone, the bundle is passed in (same pattern as prompt's `promptLog` parameter).

### Other changes

- **Layered + generic-repository P0–P2, P4** (@ZK-Andy, `6180c02`+`edc745f`+`fa1ce99`+`8e2d9da`): module-size budgets enforced by `verify-src-budgets.ts` (≤400 lines per file, out-degree ≤12); memories/skills moved onto the generic repository (same tables, no data migration); `store.ts` down 1635→370 lines of pure assembly.
- **Residual convergence A-2–A-4** (@ZK-Andy, `826f361`+`d2b4366`+`63b6ae5`): the three appliers split into per-action strategies; both schedulers state-objectified with module-level drains; assembly converged into per-kind method factories (`applySkillBatch` into services, `runPatrol` into `data/patrol.ts`, file ops as callbacks); `assembleRing` home in the ring module. Budget WARNs 10→0.
- **Script layer tail** (@ZK-Andy, `ca67c63`): deleted `record-browser-gif` (bulk-imported, zero references, dangling evidence-chain link, missing dependency); `change-scope`/`draft-release-notes` ported to TS with vitest cover; deleted the 8-line `setup-hooks.sh` (folded into one AGENTS.md line); `pre-push` calls the TS version.
- **Coverage and docs** (@ZK-Andy, `c9019d1`+`be15df7`): per-file waterline restored (including the new `data/patrol.ts` back at 100%); bilingual README synced to the `evolve_*` tools, 466 tests, 35 files, the current `src/` layout; PR template and governance hint off the retired script name; a clean rebuild clears stale `lib/` left by P7.

### Upgrade notes

- **Tool surface change**: `memory_write`/`memory_read`/`skill_write`/`skill_read` are gone; the model side calls only `evolve_write`/`evolve_read`. Update any external scripts calling the old names.
- **Marker wording change**: the first patrol after upgrade rewrites every active skill `SKILL.md` (a one-time `skillFilesReconciled` spike) — self-healing; old-marker orphans are swept in the same pass.
- **No schema change**: the underlying tables are untouched (the repository is parameterized by table); existing databases open as-is.
- dotnet-desktop is an npm copy: update to 0.16.0 and **restart the app** (`client/` untouched, no hard refresh needed).
- The review ring stays in trial mode (`review.dryRun` defaults on): this release changes no switch.
- Tests 409 → 466; typecheck, lint, coverage (97.42-92.29-100), docs gates, `check:pack` and budget gates (zero WARNs) all green.
