# 开发计划：v0.15.0 SQLite 单库记忆存储改造

> 状态：**已拍板待实施**（2026-10-06 用户拍板 B 方案）。本文是唯一执行入口，供新会话按序施工。
> 决策依据与全部调研：[`research/memory-update-retirement-survey-2026-10-06.md`](../research/memory-update-retirement-survey-2026-10-06.md)（五路调研 + SQLite spike 全绿记录）。
> 实施纪律：开工第一件事落 ADR（本计划 §8 已列 Alternatives 素材）；非平凡变更同变更携带；每阶段独立提交、测试全绿。

## 0. 拍板结论（一句话与要点）

**一句话**：这个工作区的全部记忆状态就是一个 `.evolve/memory.db` 数据库文件，插件代码是唯一写者，所有模型意图（显式指令与自动沉淀）都经结构化提案过机械门禁后由代码原子落盘。

- 存储改为 **SQLite 单库**（`node:sqlite`，宿主已验证可用，见调研 §8）：记忆条目 + FTS 索引 + 提取游标 + 账本，一个文件。
- **代码是字面唯一写者**：主会话显式"记住/忘掉"走新工具 `memory_write`；自动沉淀走提案制提取。模型在任何路径都不直接产生存储写入。
- 10-04 "无工具、文件即真相" 拍板由本改造 **supersede**（ADR 写明理由：机械门禁优先于文件透明性；工具面回归仅 1-3 个、职责单一）。
- MD 时代既有资产处置：`memory-guide.ts` 分类学搬家到提取 prompt；主会话指南缩为三行；卡片改为查库。

## 1. Schema 草案（实施时可微调，约束不可放松）

```sql
PRAGMA journal_mode=WAL;              -- 原子读写
CREATE TABLE memories (
  id TEXT PRIMARY KEY,                -- kebab slug
  type TEXT NOT NULL CHECK (type IN ('user','feedback','reference')),
  title TEXT NOT NULL,
  description TEXT NOT NULL,          -- 相关性钩子（注入索引用）
  body TEXT NOT NULL,                 -- markdown 正文；feedback 必含 Why/How（代码校验）
  status TEXT NOT NULL DEFAULT 'active'
    CHECK (status IN ('active','quarantined','archived')),
  source_session TEXT,                -- 溯源：sessionId（轨迹可回放）
  source_seqs TEXT,                   -- 溯源：seq 区间，如 "820-831"
  source_run TEXT,                    -- 哪次提取写入（显式写为 'explicit'）
  created_at TEXT NOT NULL, updated_at TEXT NOT NULL
) STRICT;
CREATE VIRTUAL TABLE memories_fts USING fts5(
  title, description, body, tokenize='trigram');   -- 中文检索已验证
CREATE TABLE extraction_log (         -- 快照账本：update/delete 内嵌 before/after 全文
  run_id TEXT, ts TEXT NOT NULL, session_id TEXT,
  trigger TEXT CHECK (trigger IN ('turn-debounce','compaction','close-drain','explicit')),
  decision TEXT, skip_reason TEXT,    -- skip 也记账（内部agent/空增量/无用户文本）
  status TEXT, duration_ms INTEGER, model TEXT, usage TEXT,  -- usage 为 JSON
  files TEXT                          -- JSON 数组：[{path/id, action, before?, after?, source_seqs}]
);
CREATE TABLE state (key TEXT PRIMARY KEY, value TEXT);  -- 提取游标 seq:<n> 等
```

要点：约束即门禁（type/status 枚举、STRICT）；账本承担回滚（`before` 快照，undo = 取 before 重写）；**不设 MEMORY.md 文件**——注入索引是查询结果。

## 2. 写路径 A：`memory_write` 工具（主会话显式指令）

- 单工具：`action: create|update|delete` + `id/type/title/description/body`，`defineTool` 注册（注意 FAQ #2：裸 `ctx.tools.register` 才需根级 required；`defineTool` 属性级 required）。
- 代码侧统一校验后落盘：id 规范、type 枚举、feedback 必带 Why/How、secret 正则筛查（复用 v1 `2026-08-28-secret-leak-guard` 模式）、update/delete 前快照旧文入账本。
- 回显给模型的 output：落盘结果 + id（供后续引用）。
- 老宿主工具注册失败 → 降级为"指南提示用户口头管理 + 控制台告警"，不阻塞注入。

## 3. 写路径 B：提案制自动提取（本改造核心）

**触发**（口径：**轮级而非步级**——`turn/end`（`agent/turn-stopping`）触发，步是轮内的模型请求周期，从不作为提取边界；ZCode 原版调用点同样在 Turn completed 之后。全有 v0.10.4 先例，`git show v0.10.4:src/turn-snapshot.ts`）：
- 每个 `turn/end` 启动/重置**空闲去抖计时器**（默认 10min，`memoryIndex.debounceMin` 可配）：计时期内无新轮才真正运行——把"连续对话每轮一次"压成"每次停顿一次"。**去抖已拍板默认开启**（2026-10-06 用户确认本口径）；去掉去抖即纯 ZCode 形态（每轮后台跑，靠合并突发控量，更及时但成本高），仅作为未来可配置的退化方向；
- 运行中有任务 → 新轮只更新最新 pending 边界，不排队不叠加（**合并突发**，单飞行调度器，确定项）；
- `session/event` 的 `compaction/start` → 强制 flush；
- 内部 agent 会话跳过（`session.header.origin`）；空增量 / 无真实用户文本（≥3 词，`Intl.Segmenter` CJK-aware）机械跳过并记账。

**执行**（单次 LLM 调用，无工具、无 agent loop——比 ZCode 更简）：
1. 代码读 `readSurface` 增量（游标后 user/assistant 文本行，有界字符）；
2. 代码用 FTS 取相似现有记忆候选（含全文）连同 manifest 一起喂模型；
3. 模型经 `outputSchema` 结构化产出提案（create/update/delete/no-op）；
4. 代码逐条校验（约束、secret、去重、feedback Why/How）→ 事务内原子应用 → 写账本（含 before/after）→ 推进游标；失败不推进。

**提取 prompt**：`memory-guide.ts` 的分类学（4a1e57d 版）搬家至此，加"边界判据：换仓库还有用才进记忆、决策走 ADR"。

**坑位**：ctx.llm 直调必须转发 host `GenerateOptions.sessionId`（缺它报 `MissingSessionID`，见 ADR `2026-09-24-direct-llm-session-routing`）。

## 4. 读路径：注入与卡片

- 开局注入：查库生成索引 section（order 400、按 agent id 会话内冻结守 prompt cache、6k 预算整行截断逻辑沿用 `memory-section.ts`）；排序 feedback > user > reference；空库零 token。
- 主会话指南缩为三行：目录/库位置一句、显式记住忘掉走 `memory_write` 一句、其余沉淀有专职流程不用管一句。
- 卡片：`memory-snapshot.ts` 改为查库（条目/搜索走 FTS/相对时间/预览不变）；"索引漂移警告"改为**巡检异常**展示；`/memory/file` 按文件名取内容路由作废，改按 id 取内容；client bundle 同步改。
- **工作区目录探测改造**（容易漏）：卡片的工作区列表靠探测各工作区记忆库存在性，从 `.evolve/memory/` 目录改为探测 `.evolve/memory.db`（或迁移标记），否则升级后工作区列表为空（`workspace-catalog.ts` + `known-workspaces.test.ts` 同步改）。
- 巡检（每次提取应用后代码执行）：约束违规（建库已挡）、orphan FTS 行、超尺寸、secret 模式 → 违规条目 `status='quarantined'`，账本记录，卡片显形；不物理删除。

## 5. 迁移与降级

- 首次启动检测 `.evolve/memory/*.md` 存在 → 逐条导入（frontmatter 解析复用 `memory-snapshot.ts` 逻辑）→ 原 MD 目录整体改名 `.evolve/memory-imported-<date>/`（不删，不丢）。
- `node:sqlite` 不可用（Node < 22.5）→ 插件降级：注入与工具停用、log 告警，宿主引导（EnsureNode）保证新装环境不触发此分支。

## 8. ADR Alternatives 素材（已在本会话辩论过，直接引用）

- **MD + 提案制（A 案）**：保留文件透明性，但门禁靠四件套拼合、跨文件无事务、frontmatter 漂移靠约定。落败：按"机械门禁唯一可信、单一职责"判据弱于 B；且 B spike 全绿后 A 无独有优势。
- **双写者（主会话顺手写 + 后台兜底）**：ZCode 同款 + eligibility 补丁。落败：兜底即双 owner，违背单一写者判据；取证证明主会话顺手写不可靠。
- **`.evolve` 内部 git**：用户否决（用户环境不能假设 git；嵌套仓库与项目 git/IDE 纠缠）。
- **JSON store 回归**：v1 遗产可复用但破坏人机共读与 ZCode 对齐；其"代码强制"内核以提案制+约束的形式回归，格式不回归。
- **SQLite + MD 投影并存**：双真相，同双写者罪，否决。
