# Agent Note: mechanical-gate-backlog

Status: proposed

> 放置路径：本文件（`.agents/notes/proposed/testing/2026-10-19-mechanical-gate-backlog.md`）。
> 2026-10-18 会话讨论了"机械校验如何校验架构/语义/形状、如何防止新功能跑偏、多语言怎么办"，结论落成本批次；细则与断言写法见 [门禁缺口清单](../../../../docs/plans/2026-10-19-mechanical-gates-backlog.md)。

## Problem

架构与质量的把关目前是**人工反复校验**：每次改动靠人读 diff、判断分层是否合理、判断测试是否真在测。已机械化的部分只覆盖 L0（形状）、L1（依赖）与 L4 的"证据存在"（ADR 格式），三块空白：

1. **L2 契约无快照**：导出面、DB 列与 CHECK、`verdict` 白名单、事件格式被悄悄改动时，只有人工能发现。
2. **L3 行为真实性无信号**：覆盖率无法区分"断言有效"与"测试恒真"；门禁自身也可能空转（2026-10-18 governance 校验恒 exit 0 即实例）。
3. **L4 决策覆盖无检查**：改了行为却不带 ADR，只能靠评审记忆。

## Proposal

按"能机械的层先做、意图层只查证据"补 12 条门禁，分三批（批次 A：G3 红绿俱验 → G1 ADR 覆盖率 → G2 依赖环 → G4 依赖棘轮），实现方式为新增 `scripts/verify-*.ts` + `test/fixtures/gates/<id>/{violation,clean}`，注册进 `run-gates` 的 docs 模式。

**铁律**：每条门禁必须先有违规样本并确认它变红，才允许接入；没有违规样本的门禁按"未实现"计。凡误报率 >10% 者降级为 warning 并在本笔记记录原因，不硬上。

L4 的"意图正确性"（该不该做、属于哪一层、Alternatives 是否真诚）不进机械校验，只保留人工批准点（新目录白名单变更、`--update` 快照、`no-adr` 标签）。

## Alternatives considered

- **只做 L0/L1**：市面工具多停在此层，漏掉"契约被悄悄改"与"测试恒真"两类最贵的腐化，等于承认空白仍在。
- **直接用 Nx / dependency-cruiser / ArchUnit**：会引入第二套规则语言与构建依赖；仓库已有 EDGES 白名单与 ts-morph，自写约 200 行更可控。
- **把 L4 交给 LLM 判定**：可被 gaming，且与项目"模型提议、代码保证"的立场冲突。
- **现在做多语言 IR + adapter**：只有一个仓库一种语言，抽象过早；等第二个语言的真实需求出现再拆 IR。
- **继续靠提示词/规则文件约束 AI**：软约束靠自觉，本批次的存在理由正是它不可靠。

## Consequences

+ 人工评审从"逐条判断"变成"看门禁报告 + 判定灰色地带"，重复劳动被收编。
+ 契约与白名单变更第一次有 diff 可见的人工批准点，迁移不再靠人眼。
+ 红绿俱验让"门禁是否真的在跑"第一次可证伪，直接防 2026-10-18 那类静默失效。

− 新增 12 个脚本与对应 fixtures，维护面扩大；每次快照变更都多一步 `--update` + ADR。
− G10（变异测试）成本高，只能抽样周跑，覆盖不到全部模块。
− 部分门禁（G8、G11）价值有限，误报可能高于收益，需按 §8 的降级规则处理。

> 前向指针：G1–G12 已由 P0＋P3（G-batch1/2/3 的 chore 提交，见 HANDOFF 滚动窗同名三条）全部落地；门禁脚本改动不单独立 ADR（G1 覆盖率门禁只管 `src/` 行为变更），缺口清单本身留作验收原文，不要当活待办重做。
