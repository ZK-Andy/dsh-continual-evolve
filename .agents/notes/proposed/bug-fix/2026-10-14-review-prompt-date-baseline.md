# Agent Note: 评审提示词缺「今天」基准（试运行分类实证）

Status: proposed

> 放置路径：`.agents/notes/proposed/bug-fix/2026-10-14-review-prompt-date-baseline.md`
> 证据来源：2026-10-12 起 dry-run 试运行累计 114 条 verdict 的逐条分类（2026-10-14）。

## Problem

试运行 3 天 114 条 verdict：`keep` 71 / `rewrite` 13 / `skip` 29 / `quarantine` 1——分布已经稳住，于是逐条读 13 条 `rewrite` 的 `reason` + `proposed` + 现存正文做分类：

| 类别 | 条数 |
|---|---|
| 可原样采纳 | 1 |
| 理由成立但拟改稿有害 | 1 |
| 正确但低价值 | 1 |
| 误判 | 10 |

**误判集中在一个形态**：8 条以「正文含**未来**日期」为由（点名 `2026-10-06` / `2026-10-07` / `2026-10-09`），而这些日期相对当天（2026-10-14）都在**过去**——评审模型没有「今天」这个基准，只能按自己的时间感把近期日期判成未来。另有 1 条是幻觉（声称正文混入评审提示语，而该条正文自 10-11 未改、实测不含提示语），成因是 `evolvePrompt` 曾把提示语贴在条目正文旁（`afb6b89` 已修提示词侧）；还有 1 条主张把本机绝对路径「泛化」，而该条记忆的价值恰恰就是本机路径。

**机制本身有效**：3 条真问题都是人容易漏掉的——把用户的一句反问升格为既定事实、钩子与正文自相矛盾（「一处」vs「两处」）、正文夹带瞬态状态。但其中 `answer-first-minimal-evidence` 那条的拟改稿会**静默删掉「硬约束」与「不重读」两段**（实测 1349 字节，两段都不在），说明「理由对」不等于「拟改稿可用」。

## Proposal

1. **dry-run 保持开启**：13 条里只有 1 条可原样采纳，放开落盘会造成真实伤害（删掉用户刚立的硬规则）。
2. **先修提示词侧**：给评审（gate / evolve）与提取的提示词提供「今天」的日期基准，日期类判断以此为参照——这是日期误判的唯一源头。
3. **拟改稿样本以 `afb6b89` 之后产生的行为准**：此前那批带回抄污染，不能用来评质量。
4. **评估口径固定**为四类：可采纳 / 理由成立但拟改稿有害 / 正确但低价值 / 误判；收口判据是「可采纳率」，当前 1/13。

## Alternatives considered

- **直接关 dry-run 让环自动改**：13 条里 10 条误判，另 1 条会删掉用户的硬规则，落盘即伤害。落败。
- **只在提示词里加一句「不要判未来日期」**：治标——根因是缺基准，模型仍按自己的时间感判断，误判照旧。落败。
- **把日期判断从评审职责里删掉**：会放过真正的时间错误（记忆里写尚未发生的事是真实缺陷，也是本次 3 条真问题之一）。落败。
- **换更强的评审模型**：成本更高，且不解决「提示词里没有今天」这一信息缺失。落败。
- **先按现有拟改稿手工挑几条落盘**：人工替环做决策，等于绕过 dry-run 的意义（看清误伤率再决定是否放权）。落败。

## Consequences

- 待实施：评审两岗（gate / evolve）与提取提示词的日期基准注入。
- 试运行观察的判据改为「分类口径下的可采纳率」；修好基准后复跑一轮再评。
- 已知边界：`afb6b89` 之前产生的 `proposed` 不可采信；日期误判在基准落地前会持续污染 `rewrite` 桶。
