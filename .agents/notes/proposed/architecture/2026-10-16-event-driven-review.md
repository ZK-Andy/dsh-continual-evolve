# Agent Note: 事件驱动评审取代到期全量重审

Status: proposed

> 放置路径：`.agents/notes/proposed/architecture/2026-10-16-event-driven-review.md`
> 讨论来源：2026-10-16 会话（正式跑验收通过后，用户质疑 30 天全量重审的规模成本，拍板事件驱动方向，拒绝临时方案）。
> 实施时机：与 `2026-10-13-memory-tiering-and-promotion.md` 同一批（提级/退休落地时一并做，不单独排期）。

## Problem

`review.staleDays`（默认 30 天）的语义是"上次成功评审超过 N 天即重新排队"，即**全量记忆每 N 天必被重审一遍**。这是 O(N) 的固定维护税，且与记忆质量无关：

1. **时间是最糙的"可能过时"代理**。记忆变质只因为事件（用户纠了它、来了条新的与它矛盾/重复、它绑的仓库机制变了），不会到日子自动变坏。用一刀切计时器近似这些事件，规模越大越亏。
2. **今日实证**：`evolve-runtime-ledger-lookup` 同一条在同一天被评审议了两次且结论翻转（keep→skip），全是 token 开销、零信息增量。N 上千后，"已决事项被反复重议"会成为常态开销。
3. **规模测算**：稳态重审量 ≈ N/30 条/天。N=1000 时每天约 33 条纯到期重审（便宜门约 600 token/条，约 1/4 进贵门约 5K），每天 4~6 万 token 固定税且随 N 线性涨；N 再大则日预算封顶、尾部丢弃，"30 天重审"的保证名存实亡，变成不透明的随机覆盖。
4. 与提级目标冲突：提级/退休机制正是要养出"活跃记忆几百上千条"的规模，全量重审会先把这条路的 token 经济堵死。

## Proposal

评审触发制改为**事件为主、时间只做兜底抽查**：

1. **事件牵连队列**（主入口）：新记忆/技能落盘时，提取轨已用 FTS 取过相似候选——把"相似即牵连"落成队列（`corrects` 指向的被替代条目本就牵连，保持）；用户纠错类 feedback 落盘时，同主题旧条目牵连。牵连即进最高优先级（现有"被纠正牵连"档位的自然扩大）。
2. **时间降级为兜底抽查**：陈旧条目不再保证全审，只进小配额抽查池；`staleDays` 语义改为"最长免审期"（超过即有资格被抽中，而非必须全审）。
3. **已决不再议**：同一条目连续 2 次 keep 且其间无牵连事件，下次免审期翻倍（30→60→120 天封顶）；出现任何非 keep verdict 或牵连事件即清零。今日"一日两议且翻转"的事不再发生。
4. **数据面**：`reviewStateOf` 返回加 `settledStreak`（连续 keep 次数，无事件即递增）；牵连队列独立于日预算优先级存在（新写 > 牵连 > 抽查），`review_daily` 的 `requeued` 只记牵连+抽中，不再 ≈ N/30。
5. **与提级的衔接**：分层差别周期（L2 高频短、L0 零查阅只等事件）归提级 ADR 管，本文只定触发制；退休归档的行不进任何队列。

## Alternatives considered

- **配额化（陈旧队列限占日预算 20%）**：改动最小，但语义不诚实（"到期重审"名存实亡）且不治"重复议价"，属用户明确拒绝的临时方案。落败原因：只延缓、不纠正。
- **调大 `staleDays`（90/180 天）**：一行配置的事，但只是把线性税的斜率调小，N 上千后同样爆炸。落败原因：同上。
- **维持现状**：小 N 下无感，但与"养出上千条活跃记忆"的既定目标直接冲突，且今日已有浪费实证。落败原因：与目标不兼容。

## Acceptance criteria

- 稳态下 `review_daily.requeued` ≈ 当日牵连事件数 + 小额抽查，而非 N/30。
- `review_log` 里同一 item 在无 intervening 牵连事件的 30 天内出现两次 verdict 且结论翻转 = 0。
- 牵连覆盖：一次"用户纠错某条"后 7 天内，被纠主题的旧条目至少被复核一次（抽查 `review_log` 可验证）。

## Risks

- **事件漏牵连**：相似阈值调得过严会漏掉真矛盾——兜底抽查保留就是对冲，阈值先宽后严。
- **已决加倍延迟纠错**：长免审期的条目若真变质会躺更久——任何非 keep 或牵连事件清零 streak 是对冲；quarantine/secret 巡检是独立通道，不受免审期影响。
- **实现复杂度**：牵连队列 + streak 列是存储变更——随提级 ADR 同一批做（本来就要动存储与优先级），不单独立项。
