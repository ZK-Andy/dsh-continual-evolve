# Agent Note: 记忆分层与两级试用提级（L0/L1/L2 + probation）

Status: proposed

> 放置路径：`.agents/notes/proposed/architecture/2026-10-13-memory-tiering-and-promotion.md`
> 讨论来源：2026-10-13 会话（评审质量 → 画像在哪 → 分层 → 提级机制）。
> 实施时机：dry-run 收口后；本文即实施单。

## Problem

1. **人物画像无家**：提取轨的归属判据说「跟人走」，存储却只按 `cwd` 分区——记忆侧**没有全局写入路径**（`GLOBAL_WORKSPACE` 只有技能在用）。实测：`chinese-preferred`（用户偏好中文）住在 work 分区，于是 dotnet-desktop 工作区开会话时注入索引里没有它，换项目即失忆。
2. **评审缺「放错分区」的处置**：现在遇到「内容对、但住错家」只能 quarantine（放错家=隔离）。`model-provider-plugins` 被判「机器侧信息、不跟人走」正是该缺口的症状——正解应是提级或降级，而不是隔离。
3. **一次判断不可靠**：若把提级做成「记录时一次判定就落全局」，误判会污染所有项目；而把「跨工作区被用过」从事前门槛去做，又会死循环（不住全局就看不到，看不到就永远拿不到证据）。
4. **行为信号闲置**：`memory_usage` 已记录条目被取用几次、最近何时，但既没喂进评审，也没用于提级考察。

## Proposal

### 分层

| 层 | 内容 | 承载 |
|---|---|---|
| **L0 人**（跨所有项目） | 协作偏好、语言、工作方式、本机环境事实 | 全局分区 `workspace_id=""` |
| **L1 项目**（仓库） | 项目现状、机制指针、命令、门禁 | 工作区分区 + 仓库文档 |
| **L2 会话/任务** | 临时状态、一次性输出 | 不进库（提取轨拦截） |

项目画像**不另建**：仓库协作体系（AGENTS.md 分层 + HANDOFF 家庭 + ADR + 门禁）本身就是它，见 [memory-update-retirement-survey-2026-10-06.md](../../../../docs/research/memory-update-retirement-survey-2026-10-06.md) §3。

### 两级试用漏斗

**阶段一｜项目内候选（记录时只打标，不落全局）**
- 提取提案加 `scope: person | project`（归属三测的自然延伸，即「抹掉仓库名还成立吗」的显式出口）；带 `person` 的条目**只入提级候选队列**，仍住原分区。
- 下一自然回炉周期复核（进 priority 1，不必等满 30 天）：两次**独立**判定（记录时 + 审查时）都指向「跟人走」+ 去仓库化测试通过（抹掉仓库名/路径/版本/开关名后句子仍成立）+ 未被 `corrects` 推翻 → 提级。

**阶段二｜全局实习（probation）**
- 提级即进全局分区，`probation_until = now + 30d`。
- **实习记忆正常进注入索引**，渲染带「试用中」标记：不注入则实习期失去考核意义——「没被用到」只是「没被看到」。
- 30 天后复审，输入带行为证据（`memory_usage`：被引用次数 + 涉及工作区）：
  - **转正**：≥1 个非来源工作区实际引用过 + 未被推翻 → 清 `probation_until`；
  - **降级**：回到提级前的**原来源分区**（已知，不需新判断）；
  - **隔离**：真过时/涉密 → quarantine。

**阶段三｜手动兜底**
- 复用技能的 `move-to-global` 形状（全局建行 + 项目行归档 + 单事务 + 永远一份 active，见 [skill-wiring-s1](../../implemented/feature/2026-10-11-skill-wiring-s1.md)），入口挂 `memory_write` 的 action。
- 默认也走实习；人工可显式「直接转正」。

### 出水管

**全局层（L0）**：

- 全局条目被审查判定「其实绑某仓库」→ **降回该项目分区**（内容没错、位置错），而不是 quarantine。
- 真过时/涉密 → quarantine。
- 只有进水管没有出水管，全局层会变成垃圾桶。

**项目层（L1）**：L1 下面就是 L2，而 L2 的定义是「不进库」——所以项目条目的「降级」不是搬到更低的存储层，而是**淘汰出库**或**搬出库外**。四向出口：

| 判定 | 去向 | 自动化 |
|---|---|---|
| 内容对、位置**高**（该在全局） | 提级到 L0（建全局行 + 项目行归档） | 自动（两级试用） |
| 内容对、位置**低**（该进仓库文档/README） | **导出建议**：账本标记 + 卡片可见，人工搬 | 半自动 |
| 错/过时/涉密 | quarantine | 自动 |
| **压根不该存在**（L2 一次性状态、当轮可推导、空话） | **归档**（`archived`：保留历史、不再注入、按 id 可查） | 自动（门槛严） |
| 内容对、位置对 | keep | — |

现状缺口：评审轨只产生 `quarantine` 一条出口；`archived` 虽在 `memories.status` 枚举里，却**没有任何代码路径能产生它**（只有技能搬运时用过归档）。于是「该提级」「该进仓库文档」「压根不该存在」三类命运全被隔离兜着——`model-provider-plugins` 的判词「应放环境或项目文档，不跟人走」正是症状：它准确说出了该去哪，却没有那条路。

两条取舍：

- **「该进仓库文档」必须半自动**：自动往用户仓库写文件会污染仓库、绕过 ADR 流程与文档门禁。这条只出建议（账本标记 + 卡片可见），搬运留给人工。
- **归档可自动但门槛严**：`archived` 是可逆状态位（不物理删、有账本、按 id 仍可查），所以允许自动；但「压根不该存在」比「内容错」主观，门槛取「**零引用 + 两次独立判定都判淘汰 + 未被 `corrects` 引用**」。**物理删除仍永远人工**——该硬保证不动。

### 唯一副本不变量

同一条知识任何时刻只有一份 active：提级 = 全局建行 + 项目行归档（不物理删），单事务原子完成；`corrects` 链与账本保持可回滚。评审与提取据此判断「这条是否已存在于别处」。

## Alternatives considered

- **记录时一次判定直接落全局**：一次判断不可靠，误判污染所有项目。落败（用户明确否掉）。
- **「跨工作区被用过」作为事前门槛**：死循环——不住全局就不会被其他工作区看到，看不到就永远拿不到证据。落败，改为事后考察（实习）。
- **影子可见（检索跨分区可见、注入不跨）来喂门槛**：为补门槛造的特殊可见性；实习制下提级后自然可见，不需要它。落败。
- **实习期只进检索、不进注入**：30 天内大概率零使用，全被判降级——实习机制失去意义。落败。
- **新建「项目画像」机制或表**：与仓库协作体系职责重叠，且违「决策走 ADR」边界（2026-10-06 已判）。落败。
- **提级后物理删除项目行**：丢历史、不可回滚，破坏可审计形态。落败，改归档。
- **照技能那样每一步手搬**：技能跨项目会自动触发行为、搬错代价高；记忆搬错只是放错抽屉且有账本。零人工目标下不适用。落败，只手动作兜底。
- **提级不带泛化改写**：提级几乎总伴随把具体表述泛化，两件事拆开会多一轮评审。落败（`rewrite + scope` 一步完成）。
- **「该进仓库文档」也自动落盘（自动写 README/docs）**：越权改用户仓库、绕过 ADR 流程与文档预算门禁，且仓库文档有唯一事实源纪律（每个事实只有一个家）。落败，只出建议。
- **给项目条目设「降到 L2」的路径**：L2 的定义就是「不进库」，没有可降的存储层；正确出口是**归档**（保留历史）或**搬出库外**（进仓库文档）。落败。

## Consequences

- 收益：人物画像有家且跨项目生效；「放错家」有多级正解（提级/降级）而非只有隔离；行为信号进入判定回路。
- 节奏与代价：**两级试用串行，最快 60 天转正**；实习记忆 30 天内对所有工作区可见（判断错误的暴露面变大，用「试用中」标记 + 出水管对冲）。
- 预期产量：自动提级会很少（可能月均 1–2 条）——人物画像本就是十几条量级，这是健康指标而非失败；L0 条数少也使「L0 优先注入」在 6k 预算内可行。
- 实施清单（需要动的面）：①记忆侧全局写入路径；②提取提案 `scope` 字段；③`memories` 加 `probation_until`（或等价位）；④候选收集按 `probation_until` 排期 + 复审喂 `memory_usage`；⑤评审 verdict 支持 `scope` 变更（含向下降级）；⑥`memory_write` 手动提级 action；⑦注入渲染加「试用中」标记 + 预算分配（L0 优先）；⑧项目层归档路径（`archived` 状态位 + 评审动作，门槛「零引用 + 两次判定 + 未被 corrects 引用」）；⑨「导出建议」的标记与呈现（账本 + 卡片，不自动写仓库）。⑧⑨与全局部分同批实施一次做完。
- 验证（实施时）：分级归属判定回归、提级事务原子性、实习期可见性、30 天复审三出口、出水管降级、唯一副本不变量。评审环自身见 [content-quality-evolution](../../implemented/architecture/2026-10-12-content-quality-evolution.md)。
