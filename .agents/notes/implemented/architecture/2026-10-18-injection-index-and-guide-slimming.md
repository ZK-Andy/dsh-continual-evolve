# Agent Note: injection-index-and-guide-slimming

Status: implemented

## Problem

2026-10-18 读取本机库的注入记录：14 条 active 记忆（10 条本工作区 + 4 条全局 L0）的索引估算 **1382 token**（`injection_log.est_tokens`）。按行成分拆开：

| 成分 | est token | 占比 |
|---|---|---|
| 描述（每条 27–96 中文字） | 843 | 61% |
| 标题 | 332 | 24% |
| id | 106 | 8% |
| 类型标签 `（feedback）` | 65 | 5% |
| 行格式与换行 | 14 | 1% |

另有每会话固定的指南文本 407 token（含边界规则行）。也就是说，17 条记忆以内的小库已经把 1776 token 的上下文用在索引上，而预算 4000 只用了 34%——问题不是预算不够，是**每一行都在为一句完整描述付费**；中文按 `estimateTokens` 的 1.5 token/字计价，描述是唯一的大头。

类型标签与块内排序是同一信息的两次表达（feedback > user > reference 已经把类型告诉读者），按行计价却要为它多付 65 token。

## Decision

索引行改为 `- [id] 标题 — 截断描述`：

- **描述在渲染层截到 20 字**并带省略号（`indexLineOf` 的 `DESCRIPTION_RENDER_LIMIT`）。写入门禁、FTS 索引、评审用的仍是全文——截断只发生在注入，不影响检索与判词。
- **类型不再逐行标注**：块内排序 feedback > user > reference 承担类型信息，指南同步写明这一点；标签从 `indexLineOf` 移除，`type` 字段保留在记录形状里（其它消费者仍读它）。
- `probationUntil`（「试用中」）与 `notWhen`（「不适用：…」）保留原样——它们是状态，不是描述。
- 指南（`memoryGuideIntro`）由三段压成两段：一段讲索引形状与 `evolve_read`，一段讲 `evolve_write` 的写入契约与沉淀归属；边界规则 `MEMORY_GUIDE_RULES` 不动（它承载换仓库判据、ADR 边界与绝对日期三条硬规则，压缩会丢事实）。

同一批真实数据实测：

| 项 | 之前 | 之后 | 变化 |
|---|---|---|---|
| 索引（14 条） | 1369 est | 853 est | -38% |
| 指南 | 407 est | 352 est | -14% |
| 整节 | ~1780 est | ~1209 est | -32% |

## Alternatives considered

- **只留标题、描述全砍**（454 est，-67%）：标题本身是句子，但短标题（如「OS：Linux」）离开描述就没有触发语境，且这条路线要求所有记忆标题都写成完整触发句——是记忆写作纪律的变更，不是渲染优化。
- **描述截 12 / 16 / 30 字**：分别 693 / 756 / 941 est。选 20 字是折中——保留「当…时用」的触发头，又不至于把一句小作文原样搬进上下文。
- **保留类型标签**（+65 est）：信息已被排序覆盖，净重复；但如果以后排序规则变化（例如按相关度排），类型标签需要回来。
- **在写时约束描述 ≤20 字**：会同时影响检索（描述进 FTS）与评审（描述是判「可用性」的输入），且存量 14 条仍需渲染侧截断。渲染侧先做，写时纪律另议。
- **调低 `memoryIndex.maxTokens`**：预算只是上限，不改变单行成本；调低只会让同样的记忆更早掉进 id-only 档，实际注入量不减反增（更多条目只剩 id）。
- **指南压到 ~200 est**：需要从库路径、工具契约、排序说明里删掉至少一项；省 150 token 换信息缺失，不划算。
- **同时清理 `state` 的 `seq:` 游标（关联决定）**：实测 101 行、约 12 KB，且 101/101 都对应磁盘上仍存在的会话（宿主共 1367 个会话目录）。按 `agent/disposed` 删不安全（应用退出时所有 agent 都会 disposed，会清掉活会话游标，导致下次续聊全量重提）；TTL 需要一个 `state` 表没有的时间列；`SessionQuery` 也没有「列出会话」的接口。**决定不裁剪**：它按会话数线性增长，不按时间增长。

## Consequences

- 索引行现在少一个字段（类型），少一截描述；读索引的人必须知道「块内顺序即类型」——指南第一段与 `docs/design.md` 同变更改写。
- 20 字截断会切在句中，省略号是唯一信号；预算档位与 id-only 降级不变。
- 每会话注入一次、会话内冻结的语义不变，prompt cache 的收益不变。
- 若还要再省，剩余杠杆依次是：标题上限（最长一条 55 字）、描述截 16 字、去掉行首 `- `。合计约 -120 est，收益已小于描述截断，暂不做。
