# Agent Note: ZCode 对齐的边界（读/写跟，治理不跟）

Status: implemented

> **superseded by** `2026-10-04-zcode-alignment-teardown`（2026-10-04）——"治理不跟"的边界已被新证据推翻，见该笔记。

## Problem

evolve v2 把读路径（开场注入记忆正文）与写路径（对话内直写）对齐了 ZCode 的持久记忆体感。用户随即提出"是不是要全面转向 ZCode 记忆路线"——但"全面"没有边界定义，容易被理解成连存储与治理层一起放弃。

数据使这个边界成为硬问题：全量会话日志（1058 文件 / 2026-08-13 → 10-01）里 `/evolve` 有量的命令恰好是**治理类**——`benchmark` 27、`plan` 9、`history` 4、`rollback` 2；而 ZCode 的记忆路线**没有治理层**（无版本、无快照、无回滚、无门禁、无 benchmark、无审计）。"全面转向"会砍掉唯一被证明有人用的那部分能力，以及 README 主张的差异化本身（模型提议，代码保证）。

## Decision

三层，逐层定边界：

- **记忆 UX 层（读 + 写）——跟 ZCode**。被动读：开场注入记忆正文，模型无需检索即用（`evolve:memory-index`，order 400）。低摩擦写：主会话直接 `evolve_add`，不等后台流水线。此层已由 evolve v2 落地。
- **存储与治理层——不跟，保留并继续加厚**。版本、快照、确定性回滚、写前校验、全局人工审批、benchmark 验证闭环、`reviews.jsonl` 审计、拒绝回路台账。理由是差异化与可审计性，不是怀旧。
- **人类可见性层（斜杠命令）——逐条裁决，不整体跟**。判据只有两条：①这条操作是否已被搬进对话（模型工具有等价路径）？②它是否是出事时才用的应急阀门？前者删、后者留、其余靠帮助分层降噪（见同日的 slash-command-pruning 笔记）。**不因为"ZCode 没有命令面"就删命令面**——ZCode 没有的那层恰恰是本项目的人类观测窗。

一句话：**ZCode 对齐的是"用起来像不像"，不是"有什么"**。

## Alternatives considered

- **全面跟 ZCode（含丢掉治理层）**：ZCode 无回滚/审计/门禁/benchmark；实测唯一有使用量的命令正是治理类，且坏记忆在 v2 下常驻 prompt（比 v1 更需要回滚与纠错），拒绝。
- **完全不跟（保持 v1 的"模型主动检索 + 命令写"）**：用户体感明确落后（v2 方案的对标动机），且实测人类从不用命令管记忆，拒绝。
- **只跟读路径、不跟写路径**：读进来的记忆没有对应的低摩擦写路径兑现，沉淀量上不去，等于白付注入成本，拒绝。
- **把治理也做成 ZCode 式隐式（无命令、无审计、模型自决）**：与核心主张"模型提议，代码保证"直接冲突，拒绝。
- **把边界写成一句口号（"UX 跟、治理不跟"）不落 ADR**：下次"要不要跟 ZCode"会重新吵一遍，且删/留命令缺少可复用的判据，拒绝。

## Consequences

- 后续任何"要不要跟 ZCode/竞品"的裁决有固定三层框架与两条命令判据，不必每次从体感重新论证。
- 新能力默认做进**对话与模型工具**，斜杠面只在"人类必须在场"时增加（审批、回滚、流水线开关、数据主权）。
- 记忆类斜杠命令不再新增：v2 之后写/读记忆的唯一入口是对话（见 pruning 笔记的剪枝结果）。
- 与 `docs/research/evolve-v2-passive-read-write-plan.md` 的"存储层不动"一致——本笔记把那一句升级为带判据的边界。
