# Agent Note: 记忆分层与两级试用提级（L0/L1/L2 + probation）

Status: implemented

> 放置路径：`.agents/notes/implemented/architecture/2026-10-13-memory-tiering-and-promotion.md`
> 讨论来源：2026-10-13 会话（评审质量 → 画像在哪 → 分层 → 提级机制）。
> 同批实施：[评审触发制改为事件驱动](2026-10-16-event-driven-review.md)；批次顺序与四裁决见 [review-and-tiering-batch-rollout](2026-10-17-review-and-tiering-batch-rollout.md)。

## Problem

1. **人物画像无家**：提取轨的归属判据说「跟人走」，存储却只按 `cwd` 分区——记忆侧没有全局写入路径（`GLOBAL_WORKSPACE` 只有技能在用）。`chinese-preferred` 住在 work 分区，dotnet-desktop 开会话时注入索引里没有它，换项目即失忆。
2. **评审缺「放错分区」的处置**：遇到「内容对、但住错家」只能 quarantine。`model-provider-plugins` 被判「机器侧信息、不跟人走」正是该缺口的症状——正解应是提级或降级。
3. **一次判断不可靠**：记录时一次判定就落全局会污染所有项目；把「跨工作区被用过」从事前门槛做又会死循环（不住全局就看不到，看不到就永远拿不到证据）。
4. **行为信号闲置**：`memory_usage` 已记录条目被取用几次、最近何时，但既没喂进评审，也没用于提级考察。

## Decision

### 分层

| 层 | 内容 | 承载 |
|---|---|---|
| **L0 人**（跨所有项目） | 协作偏好、语言、工作方式、本机环境事实 | 全局分区 `workspace_id=""` |
| **L1 项目**（仓库） | 项目现状、机制指针、命令、门禁 | 工作区分区 + 仓库文档 |
| **L2 会话/任务** | 临时状态、一次性输出 | 不进库（提取轨拦截） |

项目画像不另建：仓库协作体系（AGENTS.md 分层 + HANDOFF 家庭 + ADR + 门禁）本身就是它。记忆侧的全局布局是 `list/get/search` 把 `""` 分区的行合并进每个工作区的视图，**L0 排在 L1 之前**，同 id 时活动的本地行遮蔽全局行（归档行遮蔽不了任何东西——提级后的源行正是归档状态）。卡片的分区视图不合并，否则每行会出现两次。

### 两级试用漏斗

**阶段一｜项目内候选**：提取提案带 `scope: project|person` 标记（归属三测全过才写），条目仍住原分区；评审的第二次独立判定（`promotionQueue` 里 `scope='person'` 且已有一次完整判词的行）说 promote 才移动。

**阶段二｜全局实习**：提级即进全局分区，`probation_until = now + 30d`，`origin_workspace` 记住来源分区。实习行**正常进注入索引**并带「（试用中）」标记——不注入则实习期失去考核意义。到期由队列的时钟档送去复审，按 `memory_usage` 里**非来源分区**的引用数决定三出口：≥1 转正（清 `probation_until`）、0 降级（回 `origin_workspace`）、真过时/涉密则隔离。

**阶段三｜手动兜底**：`evolve_write(kind=memory, action=move-to-global)` 复用技能的搬运形状（全局建行 + 项目行归档 + 单事务），默认也进实习。

### 出水管

- 全局层：被判定「其实绑某仓库」→ 降回该项目分区（`demote`）；真过时/涉密 → quarantine。
- 项目层四向：该在全局 → 提级；该进仓库文档 → **只出建议**（判词 `export-suggestion`，卡片显形「建议入仓文档」，不自动写用户仓库）；错/过时/涉密 → quarantine；压根不该存在 → `archive`（保留历史、不再注入、按 id 可查）。
- 归档门槛严：**未被任何活动条目 `corrects` 指向 + 至少有一次历史淘汰判定（本次是第二次独立判定）+ 零引用**；物理删除永远人工。

### 唯一副本不变量

同一条知识任何时刻只有一份 active：提级 = 全局建行 + 项目行归档，降级 = 反向，均在单事务内完成；目标分区补一条 `promote`/`demote` 判词行，使搬过去的行读作「已判」而不是「新写」。

## Alternatives considered

- **记录时一次判定直接落全局**：一次判断不可靠，误判污染所有项目。落败（用户明确否掉）。
- **「跨工作区被用过」作为事前门槛**：死循环——不住全局就不会被其他工作区看到，看不到就永远拿不到证据。落败，改为事后考察（实习）。
- **影子可见（检索跨分区可见、注入不跨）来喂门槛**：为补门槛造的特殊可见性；实习制下提级后自然可见。落败。
- **实习期只进检索、不进注入**：30 天内大概率零使用，全被判降级——实习机制失去意义。落败。
- **新建「项目画像」机制或表**：与仓库协作体系职责重叠，且违「决策走 ADR」边界（2026-10-06 已判）。落败。
- **提级后物理删除项目行**：丢历史、不可回滚，破坏可审计形态。落败，改归档。
- **照技能那样每一步手搬**：技能跨项目会自动触发行为、搬错代价高；记忆搬错只是放错抽屉且有账本。落败，只手动作兜底。
- **提级不带泛化改写**：提级几乎总伴随把具体表述泛化，拆开会多一轮评审。落败（`rewrite + scope` 一步完成）。
- **「该进仓库文档」也自动落盘**：越权改用户仓库、绕过 ADR 流程与文档预算门禁，且仓库文档有唯一事实源纪律。落败，只出建议。
- **给项目条目设「降到 L2」的路径**：L2 的定义就是「不进库」，没有可降的存储层；正确出口是归档或搬出库外。落败。
- **用单独一张表记「提级来源」**：多一张表只为记一个分区字符串；`memories.origin_workspace` 一列即可，且随行归档一起进历史。落败。

## Consequences

- **落地**：v0.18.0。存储列 `scope` / `probation_until` / `origin_workspace` 与判词白名单扩到 `archive/promote/demote/export-suggestion` 在 `data/schema.ts` + `data/migrate.ts`；提级事务与门槛在 `data/tiering.ts`；评审出口在 `services/review-tiering.ts`；注入合并与「试用中」标记在 `store.ts` 与 `surfaces/memory-section.ts`；卡片建议标记在 `surfaces/memory-snapshot.ts` + `client/client.js`。
- 收益：人物画像有家且跨项目生效；「放错家」有多级正解而非只有隔离；行为信号（跨分区引用）进入判定回路；项目的「该进仓库文档」有了诚实出口。
- 节奏与代价：两级试用串行，最快 60 天转正；实习记忆 30 天内对所有工作区可见（判断错误的暴露面变大，用「试用中」标记 + 出水管对冲）；自动提级预期很少（月均 1–2 条），这是健康指标而非失败。
- **验证**：`test/tiering-store.test.ts`（迁移/幂等/scope 门禁）、`test/tiering-review.test.ts`（提级事务与唯一副本、跨区可见、降级、归档三门槛、时钟档、四种 verdict 落地、导出建议与卡片标记）共 22 例。
- 已知边界：技能没有层级（不提级、不归档），拿到这些 verdict 时落 `verdict-not-applicable` skip 行；实习转正只看「非来源分区引用」，30 天窗口内没有真实跨项目使用就退回——比"再等等"更诚实。
