# Agent Note: 评审触发制改为事件驱动

Status: implemented

> 放置路径：`.agents/notes/implemented/architecture/2026-10-16-event-driven-review.md`
> 讨论来源：2026-10-16 会话（正式跑验收通过后，用户质疑 30 天全量重审的规模成本，拍板事件驱动方向，拒绝临时方案）。
> 同批实施：[记忆分层与两级试用提级](2026-10-13-memory-tiering-and-promotion.md)；批次顺序与四裁决见 [review-and-tiering-batch-rollout](2026-10-17-review-and-tiering-batch-rollout.md)。

## Problem

`review.staleDays` 原本的语义是"上次成功评审超过 N 天即重新排队"，即**全量记忆每 N 天必被重审一遍**。这是 O(N) 的固定维护税，且与记忆质量无关：

1. **时间是最糙的"可能过时"代理**。记忆变质只因为事件（用户纠了它、来了条新的与它矛盾/重复、它绑的仓库机制变了），不会到日子自动变坏。
2. **实证**：`evolve-runtime-ledger-lookup` 同一条在同一天被评审议了两次且结论翻转（keep→skip），全是 token 开销、零信息增量。
3. **规模测算**：稳态重审量 ≈ N/30 条/天。N=1000 时每天约 33 条纯到期重审，日预算很快被它吃掉，尾部丢弃让"30 天重审"名存实亡。
4. 与提级目标冲突：提级/退休正是要养出"活跃记忆几百上千条"的规模，全量重审会先把这条路的 token 经济堵死。

## Decision

评审触发制是**事件为主、时间只做兜底抽样**：

1. **事件是主入口**。`item_events` 记三类牵连：`similar`（新落盘与既有条目字面相近）、`corrects`（落盘条目显式指向它）、`correction`（用户纠错类 feedback 落在同一主题）。事件与正文**同事务**写入；pending 判据是「事件 ts 晚于该条目最近一条**完整**判词」——失败判词不消费事件。
2. **时间降级为抽样**：`staleDays` 是「最长免审期」，超过只是**有资格**被抽中；抽样名额取批量的五分之一（至少 1 条），按最久未审优先，其余名额给新写与事件。
3. **已决不再议**：keep 连击（最近一次重置点之后的连续 keep 终局判词）≥2 使免审期 ×2、≥4 使 ×4（30→60→120 封顶）；任何非 keep 判词或牵连事件把连击清零。连击**派生自判词行**，不物化列——判词与事件都不必双写，裁剪后自然归零（偏保守）。
4. **账目分来源**：`review_daily.requeued` 恒等于 `requeued_link + requeued_clock + requeued_sampled`，由 `mergeDaily` 求和得出，调用方不传总数。
5. **搬迁与评审改写不产生事件**：提级/降级/归档在目标分区写一条判词行作为「已判」凭据；纯正文 update 不牵连邻居，否则评审的改动会把邻居拉回队列。
6. **老纠正链不丢**：被 `corrects` 指向的条目即使没有事件行也进队——本版之前写下的纠正关系不因换触发制而消失。

## Alternatives considered

- **配额化（陈旧队列限占日预算 20%）**：改动最小，但语义不诚实（"到期重审"名存实亡）且不治"重复议价"，属用户明确拒绝的临时方案。落败原因：只延缓、不纠正。
- **调大 `staleDays`（90/180 天）**：一行配置的事，但只是把线性税的斜率调小，N 上千后同样爆炸。落败原因：同上。
- **维持现状**：小 N 下无感，但与"养出上千条活跃记忆"的既定目标直接冲突。落败原因：与目标不兼容。
- **物化 `settledStreak` 列**：判词与事件都会重置它，物化要两处同步写、一处漏写即漂移，裁剪还会让列与实际判词脱节。落败原因：派生读的成本远低于双写的一致性风险。
- **把「已决」做成配置开关灰度**：多一个状态位、多一套口径，而不开豁免本身是安全的。落败原因：引入无行为收益的状态。

## Consequences

- **落地**：v0.17.0（`0e6bd8b` 事件表与牵连写入、`b6978b6` 队列决策表与账目分列）。表在 `data/item-events.ts`，队列在 `services/review-candidates.ts`，牵连规则在 `services/memory-linkage.ts`。
- **验证**：`test/review-events.test.ts`（事件写入、待办判据、连击派生、裁剪）与 `test/review-queue.test.ts`（档位顺序、抽样配额、免审倍数边界、日账恒等式）共 24 例。
- 稳态观测项（`review_daily` 三列占比、重复议且翻转 = 0、事件产量）记在 `/mnt/work/work/OBSERVATION.md`。
- 代价：N 大时 20% 抽样覆盖慢（1000 条陈旧条目约 15 天一轮）——事件是主入口，抽样只作对冲；相似阈值取「先宽后严」，收紧点只有 `linkageToken` 一处。
- 风险对冲：漏牵连由抽样兜底；长免审期的条目若真变质，任何非 keep 或事件都会清零连击；quarantine/secret 巡检是独立通道，不受免审影响。
