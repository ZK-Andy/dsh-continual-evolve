# Agent Note: 记忆提取边界收窄为"跟人与环境走的知识"

Status: implemented

## Problem

2026-10-05 的会话取证（DSH session-5923f8f9）确认：真实使用会话中的纠正与偏好信号没有进记忆库，沉淀率近似零。进一步核查推翻了取证会话的一个关键前提——"ZCode 原版靠每个成功回合调度后台提取 agent"（实际原版即本插件同款形态：系统提示指南 + 主会话模型原生直写，无任何机制）。真正的差距在注入指南自身：

1. intro 把写记忆定位成"在同一会话内**顺手落盘**"的副产品——而取证恰恰证明副产品永远输给主任务；
2. `when_to_save` 的 `project` 类型（"进行中的工作、决策、截止期"）与仓库 ADR 纪律职责重叠，既漏掉真正的决策（该走 ADR），又诱导产出低复用价值的决策型记忆且无退役出路；
3. 指南整体过长（四组 type 文档带示例），信号稀释；
4. 缺一条"当轮就写"的硬规则。

用户拍板（2026-10-06）：记忆提取走类似本仓库 ADR 提取的路线，记忆库定位收窄为**用户画像 + 基本知识**；决策与取舍一律走 ADR，不进记忆。

## Decision

`src/memory-guide.ts` 按此边界重写：

- 类型枚举从 `user | feedback | project | reference` 收窄为 `user | feedback | reference`：`user` 承载画像与环境事实（含机器、工具链、配置位置），`feedback` 承载协作纠正与确认（必带 Why / How to apply），`reference` 承载资源指针；`project` 语义退役。
- 新增**边界判据**："换一个仓库还有用的信息才进记忆"——决策、架构取舍、进行中状态只对当前仓库有价值，走仓库 ADR/文档路线，不进记忆库。
- intro 删除"顺手落盘"表述；`when_to_save` 首句改为**当轮就写**硬规则（纠正/拍板出现的那一轮就写，不留到会话后期）。
- 指南整体砍短，删去 `project` 组与冗余示例。

存量无迁移：现存两个 store 文件的 type 均为 `user`/`reference`，无 `project` 条目。

## Alternatives considered

- **回合后自动提取（每回合或会话收尾派后台子代理）**：复刻一个被误读的"ZCode 原版机制"；会话收尾时机不可靠（关窗/崩溃时钩子不执行），子代理拿不到父会话上下文、喂 transcript 的 token 成本高。落败：机制解决的是不存在的问题。
- **保留 `project` 类型但重写其语义**：类型名本身就在诱导模型记录仓库状态，语义漂移会复发；且与"决策走 ADR"的边界永远存在判别摩擦。落败。
- **维持原指南，只追加"当轮就写"一句**：`project` 类与 ADR 职责重叠的核心问题不解决，低复用记忆照产。落败。

## Consequences

代价：指南变短，类型判别示例减少；frontmatter 枚举变化意味着未来出现 `type: project` 旧文档即不合规（现存 0 条，读时验证兜底）。收益：记忆库与 ADR 路线职责清晰，入库条目天然高复用，"沉淀什么"与"如何退役"两个问题同时收敛；注入 token 显著下降。
