# Agent Note: 落点测试——事实的家由「落进仓库」这个动作决定，不由文件名决定

Status: implemented

## Problem

2026-10-16 实证：用户在会话里说「把这条记入 agent.md 置顶」，同一轮 agent 把该规则写进了 `AGENTS.md`，提取轨随后仍创建了一条记忆 `no-flattery-honest-feedback`（run `extract:session-c09e3975…:91`）。账本里它的理由原文是「跟人走、不随仓库变化，**且现有记忆无此条**」——只与记忆比对，从未与仓库文件比对。结果：同一个事实两个家，且两边措辞已经开始漂移。

根因有三层，都在提取侧：

1. 提取器的「家」只有两个——记忆，与 ADR/docs（且后者只对「仓库事实」生效）。「别奉承」按归属三测（主语是人、去名后仍成立、不是仓库机制）全部通过，模型判定它是合法的「跟人走」偏好。
2. 提示词没有任何「落点」概念：用户指定落进仓库文件的动作，在 prompt 里没有对应判据。
3. 增量里看不见动作：`serializeIncrement` 只序列化 user/assistant 文本，工具调用整行丢弃，模型无从知道「这一轮发生过文件写入」。

## Decision

- 提取系统提示词在归属三测之外增加**落点测试**：用户本轮已把事实写进、或明确要把它写进仓库里的某个文件，该文件就是它的家，判 skip 并在 `reason` 里引用用户原话。判据只看「已落进仓库」这个动作，**不枚举任何文件名、目录或文件名模式**——落点叫什么、是不是新文件，都与插件无关，因此新增或改名工作区文件永远不需要插件发版。
- `serializeIncrement` 在增量头部加一行 `tools-this-turn: <工具名>`：只取工具名，参数与路径永不进入 prompt。行首位置保证尾部截断时不丢；字符预算按「该行长度 + 1」扣减，超长工具名截到 40 字符、最多 20 个去重名字，整体仍受 `maxChars` 约束。
- 便宜预检门同步一句落点判据（任何名字都算，只看动作），让「已落仓库」的事实连贵调用都不触发。
- 回归测试钉住两条设计约束：提示词里出现「落点测试」与 `tools-this-turn`；提示词**不得**出现任何具体文件名（`AGENTS.md` / `CLAUDE.md` / `README` / `.agents/notes`），防止日后有人把它改回文件名清单。

## Alternatives considered

- **在提示词里列出「家」的文件名清单（AGENTS.md、CLAUDE.md、docs/** 等）**：落败——每出现一种新约定文件就要改插件并发版，且清单必然漏；判据应挂在动作上，不是名字上。
- **提取时读取工作区根规则文件正文注入 prompt**：落败——「哪些文件算家」仍需枚举；每次提取多读多传，规模随仓库增长，且读到的多半与增量无关。
- **硬判：本轮出现写类工具调用就整轮 skip**：落败——多数正常会话都会写文件，会误杀真正跨仓库的偏好；工具行只作为证据交给模型，不代替判断。
- **review 侧对已存记忆做仓库全文查重**：本轮不做——改写后的措辞检索不到，成本随仓库线性增长；真正要防的是入口，出口的重排在用户裁掉后另立笔记。
- **只靠用户说「记到 X」的措辞规则（正则匹配「记入/写进」）**：落败——同义表达无穷，正则清单同样是「新增就要改插件」，且无法覆盖助手自述「已写入」的情形。

## Consequences

- 用户的规则落进仓库文件后，提取轨不再复制一份记忆；同一个事实只有一个家。
- 增量每次多一行元信息（通常 < 200 字符），正文预算相应减少；便宜门的 4KB 头部同样带上这一行。
- 模型现在知道「本轮有文件写入」，但仍需自己判断哪条事实落进了哪个落点；漏判的兜底是 `reason` 必须引用用户原话，事后可从 `extraction_log` 复核并回放。
- 插件与工作区文件名彻底解耦：新增 `AGENTS.md` 之外的任何规则文件，都不触发代码或发版动作。
