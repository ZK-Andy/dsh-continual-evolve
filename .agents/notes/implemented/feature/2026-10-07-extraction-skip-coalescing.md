# Agent Note: 提取账本的空转跳过合并为一行计数

Status: implemented

## Problem

2026-10-07 用真轨迹对账提取轨（逐条比对会话事件与账本行）时确认：判定没错——真实用户发言一条不漏，`no-user-prose` 全部落在"确实没有用户发言"的区间（自动续跑与子代理回传的回合不产生用户 prose）。问题出在**记账粒度**：这类空转跳过**每个回合写一行**，2026-10-07 当天 22 行账本里 16 行是它。

结果是审计信号被行数淹没：`extraction_log` 的用途是回答"提取轨被唤醒了几次、每次做了什么"，而同一游标位置的重复唤醒会膨胀成几十行长得一样的现象记录——既看不出"这是同一件事发生了 16 次"，也让"提取轨根本没被唤醒"与"被唤醒了但什么都没做"在肉眼层面难以区分。

## Decision

账本区分**空转型跳过**与**其他一切**，前者连续合并为一行并计次：

- `extraction_log` 新增 `occurrences INTEGER NOT NULL DEFAULT 1`。DDL 覆盖新库；已存在的库在 `openMemoryStore` 里经 `pragma_table_info` 检测后 `ALTER TABLE … ADD COLUMN` 补齐（插件是库的唯一写者，这是账本唯一的迁移）。
- `logSkipped` 对空转型跳过（`no-user-prose`、`no-new-events`）做**连续合并**：该会话最近一行同状态同原因时，`occurrences += 1` 并把 `ts` 刷新为本次；否则插入新行。
- 只合并**紧邻的同类**。中间只要落了任何一行——模型判定、应用批次、另一个原因、另一个会话——就另起一行。这与"同一游标位置"等价：游标只在模型判定与应用时前进，而它们各自成行，所以两种口径无需把游标存进账本。
- `ts` 刷新为**最新一次**。`mostRecentlyActiveWorkspace()`（卡片默认工作区）以账本 `MAX(ts)` 作为"会话在此工作过"的信号；保留首次时间会让一个只有空转跳过的分区看起来已经失联。
- 故障型跳过（`no-route` / `no-surface` / `no-workspace`）与全部 `failed` **保持逐次成行**：持续故障该留时间线，不该被压成一个计数器。

## Alternatives considered

- **空/全合成增量干脆不记账**：行数最省。落败原因：丢掉"被唤醒过几次"的经济性证据，且与"事件根本没触发"不可区分——账本正是为审计这条经济性而存在的。
- **次数写进 `skip_reason` 文本**（如 `no-user-prose ×7`）：不动 schema。落败原因：把结构化字段降级成展示串，按原因查询与聚合全部失效。
- **单独一张按 `(workspace, session, reason, cursor)` 累加的计数表**：语义最干净。落败原因：多一张表、多一套写入路径；而账本被设计成"唯一可裁剪表"（`pruneLedger`），审计行分居两表就无法一起裁剪。
- **复用 `files` 列塞 `{"coalesced": n}`**：零迁移。落败原因：`files` 已是三态（应用行=变更快照数组、解析失败行=模型回答原文、其余 NULL），加第四种含义会迫使每个读取方按 `status` 分支解析。
- **按 `(workspace, session, reason)` 无条件合并**（不限连续）：实现更简单。落败原因：会把"游标前进之后又出现的同类跳过"并进同一行，等于把两个不同游标位置的事实混为一体，账本失去分段能力。
- **给每次唤醒都保留首次时间**（`ts` 取首次、另加 `updated_at`）：时间线更完整。落败原因：为一个展示层诉求给账本加第二时间列，而合并本身已经放弃了逐次时间线；需要逐次时间线时应直接看会话轨迹。

## Consequences

- 一个会话的连续空转轮次收敛为一行：`occurrences` 给出唤醒次数，`ts` 给出最后一次，行数不再随自动续跑轮数增长。
- 空转链的**首次**时间不再留存（只留最新 + 次数）；需要逐次时间点只能回会话轨迹。这是本次合并有意付出的代价。
- 故障型跳过保持一行一次，因此"配置坏了每回合刷一条"仍能第一时间显形。
- 迁移在 `openMemoryStore` 内幂等执行：旧库（含 dotnet-desktop 正在使用的 0.15.2 库）首次被新版本打开时补列，历史行回填 `occurrences = 1`。
- 测试 190 → 194（store 三例：连续合并与断链另起行、跨会话与故障型不合并、旧库补列迁移；extraction 一例：真路径连续三次空转合成一行）。`docs/design.md`、双语 README 的记账口径同步改写。
- 随 **v0.15.3** 发版（与 `6454281` 的失败留痕同一版）：dotnet-desktop 更新后首次打开既有库即补列，合并口径随之生效。
