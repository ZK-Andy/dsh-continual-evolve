# Evolve Memory Creator（自创）

> 自创技能，与 `evolve-skill-creator` 同结构（访谈 → 正文 → 自检），内容规则来自本项目 `memory-rules.ts` 的机械门禁。只产出**内容**（类型＋标题＋钩子＋正文），不写任何落盘指令——存储由插件代码负责。

## 先分类（写错类型等于写错记忆）

只收三种，收不进去就不是记忆：

- `user`——用户画像与环境事实（系统、偏好、网络、工具链）。判断：换一个仓库还有用吗？有用才收。
- `feedback`——用户纠正/确认的做法规则。正文必须带 `**Why:**` 与 `**How to apply:**` 两行，缺一行就不是 feedback。
- `reference`——将来会用的资源指针（链接、路径、版本号）。

仓库版本细节（某次提交的数字、某版行为）归 ADR/docs，不进记忆。决策过程不进记忆，只进 ADR。

## 访谈（动笔前问清三件事）

1. 这条记忆以后在**什么场景**被想起？（说出 1–2 个具体未来场景，说不出就是伪需求。）
2. 钩子怎么写才能在那个场景被检索到？（把场景里的关键词原样放进钩子，不要同义改写。）
3. 是新建还是更新？（先检索：同 id 或同正文已存在就更新那条，不开第二条。）

## 正文结构

- **标题**：一句话，不超过 200 字。中文标题允许（id 会走哈希兜底，但标题本身照写中文）。
- **钩子**（description）：一句话相关性说明，不超过 500 字。这是未来会话会不会想起它的唯一依据——写"何时用"，不复述正文。
- **正文**（body）：事实本身或规则全文，不超过 65536 字。feedback 型先写规则，再写 `**Why:**`（为什么定这条）与 `**How to apply:**`（以后遇到什么情况怎么做），两行缺一不可。

## 本项目门禁（写完逐条自检，不过就改）

- [ ] 类型是三者之一；标题、钩子、正文齐全且非空。
- [ ] feedback 型带齐 `**Why:**` 与 `**How to apply:**`。
- [ ] 全文不带任何密钥痕迹（同 skill 标准）。
- [ ] 正文里没有持久化指令：不出现"调用 memory_write""记住这条""存入全局"这类句子。成稿后把正文交给用户，由调用方落盘。

## 不做

- 不写相对日期（"下周三"→写绝对日期如 2026-10-22）。
- 不把一次性的版本号、测试数字写成记忆（那是 ADR/测试报告的家）。
- 不做"记忆评分/重要性"——检索靠钩子，不靠分值。
